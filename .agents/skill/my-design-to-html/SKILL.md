# 技术方案 HTML 阅读版

把已有设计整理成程序员能快速理解、逐段审阅的单文件 HTML。默认沿用本项目第 13 课阅读版的内容密度与浅底绿色样式。完成范围是阅读呈现；技术决策继续由输入方案维护。

## 输入与输出

- 输入：用户指定的技术方案、实际关联的代码设计附录，以及本次明确的阅读偏好。未指定文件时，从当前 Feature 的有效设计入口定位；多个候选影响内容时再澄清。
- 默认输出：方案同目录的 `TECH_DESIGN.html`；已有同用途 HTML 则原位更新。不同用途文件占用该路径时选用 `TECH_DESIGN.review.html`。
- 编辑源：方案旁的 `document/` 中维护阅读版 `guide.md`、`edition.json` 和按需 SVG。已有生成链路可继续复用，避免覆盖既有配置。仅在新增配置确有冲突时使用 `document/review/`。
- HTML 内嵌样式、交互、代码高亮和预渲染 SVG；单文件移走后仍可离线阅读。截图、临时副本和检查记录放项目 `work/`，不加入阅读正文。

## 内容取舍

先读 [内容与视觉契约](references/reading-contract.md)，再提炼方案。以下顺序是默认阅读路径，章节按实际设计裁剪：

1. **目标**：正文第一节，三列 `核心问题 / 实现目标 / 量化指标（设计目标）`。指标采用方案已有次数、时间、容量、数量或可判定不变量；缺少数字时写“未设定”，保留原有定性目标。
2. **方案概述**：职责分层表与一张整体架构图，让读者知道新增什么、由谁负责、如何连接。
3. **详细设计**：按需选择数据模型、组件关系、请求时序、状态、关键策略、输入输出契约。图表达关系与过程，表解释字段、规则与边界。
4. **变更文件与变更内容**：用 `text` 代码块列出文件树，每个相关文件带 `[新增] / [调整] / [生成]` 与一句职责变化。
5. **核心类型与代码**：保留能判断设计质量的类型、签名和关键分支；复杂算法从原代码附录直接提取，外围样板按需省略。

默认以表格、Mermaid/SVG、代码块组织正文。长段落改为这些表达形式；少量必要句子可放入表格或图注。省略需求依据、验收矩阵、评审结论、文档索引、部署、验证与兼容章节。用户显式要求保留的内容优先。并发、重试、状态和输出约束属于方案本身时保留其设计。

禁止补造性能提升比例、生产 SLA、实测数据、已通过评审状态或尚未设计的接口。原方案中的关键缺口保留为表内“待确定”；需要改变核心决策的冲突单独反馈，不在排版过程中替用户定案。保留命名、默认值、所有权、错误语义和关键算法；代码片段默认标为设计示意。

## 生成与更新

1. 核对源方案及关联附录。将设计信息整理进阅读 `guide.md`，使用 [章节模板](assets/guide.template.md) 选择需要的图、表和代码。章节模板是组织参考，示例说明不进入输出。
2. 按 [生成配置](references/generation.md) 创建 `edition.json`。源代码通过 `{{code:名称}}` 引用配置中的文件与唯一匹配符，减少维护副本。标题、主题词、首屏数字卡和 SVG 按实际方案填写；无适合内容时省略可选展示。
3. 使用本 Skill 自带的 `scripts/render.mjs` 生成 HTML。固定依赖见 `package.json` 与锁文件，安装和命令在生成配置文档中。运行时从 Skill 自身解析资源，不引用特定课次的渲染器、目录或应用包。
4. 检查新产物。先运行 `scripts/check-html.mjs` 验证独立离线打开、代码复制/展开、搜索、图表缩放/导出、锚点、打印和窄屏滚动；再查看目标表、最密集图、最长代码块的桌面与窄屏截图，修正遮挡和小字。
5. 核对内容：目标指标与设计一致；关键分支与原代码一致；变更清单覆盖当前设计；没有模板残留与工作流章节。维护最近的 README 中的生成入口；保持 Feature 阶段及源方案状态。

更新时先改阅读编辑源再重建 HTML。如果用户明确修改技术设计，将其决策同步到有效源方案后再生成，避免两个维护入口出现不同结论。

## 完成与评测

最终给出 HTML 的本地可点击链接和简短完成说明。无需自动发布、提交代码、调用方案评审或推进实施阶段。

维护 Skill 时运行 `npm test --prefix <Skill目录>` 及 Skill frontmatter 校验；内容裁剪与缺失指标场景按 [评测说明](evals/README.md)复核。模板源来自第 13 课已认可的阅读风格，后续通用模板维护在本 Skill，既有课次产物保持各自生成入口。
