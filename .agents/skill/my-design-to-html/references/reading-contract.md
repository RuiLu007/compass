# 内容与视觉契约

## 阅读层次

| 层次     | 读者应当理解的内容                     | 表达方式                                        |
| -------- | -------------------------------------- | ----------------------------------------------- |
| 目标     | 当前问题、期望行为与可量化边界         | 三列表；通常 3–6 项，按问题规模增减             |
| 整体设计 | 入口、核心模块、数据所有者、依赖方向   | 架构图 + 职责表                                 |
| 详细机制 | 实体关系、状态迁移、核心路径、关键分支 | 对应的 ER / UML / 时序 / 流程图，配字段或规则表 |
| 文件变化 | 开发者将在哪些文件中实现什么           | 带变更描述的文件树代码块                        |
| 代码设计 | 类型形状与决定行为的算法               | 完整关键代码；从附录直接提取                    |

详略取决于方案复杂度。几处配置调整可以只有目标表、前后对比和文件清单。涉及状态、并发、所有权或跨模块契约时，展开相应机制，避免用空函数、TODO 或省略号隐藏关键分支。无需为所有方案凑齐每一种图。

## 目标与指标

- 指标列明确标记为设计目标。已有实测值仅在源方案明确给出时按其口径展示。
- 数量上限必须带作用域，如每次逻辑调用、单进程、每个租户；时间预算写清起止范围。
- 100% 校验覆盖、失败内容提交数为 0 等不变量可以作为设计目标；结构校验、语义正确率与线上成功率使用各自的定义与口径。
- 源方案没有量化口径时使用“未设定”。用户要求补指标后，再提出标明待确认的建议。
- 不沿用示例的业务实体、2 次尝试、180 秒、8/32 容量、课次编号或日期。

## 信息分配

| 信息                                   | 处理方式                                   |
| -------------------------------------- | ------------------------------------------ |
| 同一概念的散落描述                     | 合并为一处职责、字段或规则表               |
| 多组件交互与分支                       | 放进图；必要条件放邻近表格                 |
| 大段“类 A 调用类 B”                    | 改为组件图或时序图                         |
| 关键代码                               | 保留原语义，使用代码引用；标清语言与模块   |
| 纯样板、重复类型                       | 只保留当前审阅需要的部分，表内说明省略范围 |
| 文件任务                               | 文件树 + 变化描述，生成文件标为 `[生成]`   |
| 背景、依据、AC、评审结论及操作手册     | 默认从阅读版省略，继续留在原方案           |
| 当前设计中的故障、权限、取消与并发语义 | 保留影响理解和判断的设计，不附扩展治理清单 |

## 视觉与交互

- 浅暖白底、深绿色文字、淡绿表头与图形；系统中文字体与等宽代码字体，无外部字体请求。
- 单栏正文，内容宽度约 1120px。桌面正文、表格和代码约 14px、辅助文字约 12–13px；窄屏保留可读字号，表格与代码各自滚动。
- 目标表排在正文首位。顶部只保留少量直达导航和搜索，不添加大目录或文档索引章节。
- Mermaid 在构建期转 SVG；宽图可横向滚动，长图不压成固定高度的小字。单图过密时按职责拆图，保持关系完整。
- 图表可放大、缩放、下载 SVG，并保留可复制源码。代码可复制，长代码可展开；搜索结果能打开折叠内容并定位。
- 采用原生按钮和 dialog，键盘可操作、焦点可见、Esc 关闭；尊重减少动态效果偏好。打印展开代码并移除交互控件。
- 首屏可使用来源明确的数字卡和自绘 SVG；没有合适内容时省略，避免模板装饰替代设计信息。

## 风格来源

本 Skill 提炼自 Compass 第 13 课的 `design/TECH_DESIGN.html` 与本次用户协作：先收敛为图、表、代码和文件清单，再在正文首位加入目标表及量化指标列。生成其他方案时，复用信息结构、密度和视觉语言，业务内容从当前输入重新提取。
