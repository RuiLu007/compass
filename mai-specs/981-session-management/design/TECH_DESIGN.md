# 分析会话标题与管理

[返回需求](../BRIEF.md) · Feature 981 · simple 档 · 基线 `9b62205` 及当前 Runtime 工作区。依据为用户在本次会话确认的方案，按简版技术设计模板记录。

## 需求依据与验收

- AC1 首次发送后侧栏立即显示首条消息派生的临时标题。Agent 独立调用模型，生成同语言短标题并持久化。分析完成、连接关闭和重新打开页面后均可读取最新标题。
- AC2 会话行右侧的三点菜单支持鼠标、键盘和触屏操作。改名后列表立即更新，手动标题在刷新后保留，优先于后台自动标题。
- AC3 删除前确认。任务处于非终态或资源清理未确认时拒绝删除。删除成功后撤销会话、消息及所属运行产物的用户入口。删除当前会话后返回新建分析。

## 实现

新建 Session、首条消息和待生成标题状态在同一事务内提交。首次受理响应携带一条会话元数据，Web 按同一 ID 加入侧栏。Agent 用短事务领取标题任务，锁外通过现有模型服务完成生成。Auto 选 Flash，固定模型沿用首条消息所选模型。调用仅携带首条问题，使用文本输出并限制时长和输出长度。两次尝试后保留临时标题。领取记录包含尝试次数和租期，Agent 重启后可取回到期任务。

生成结果在短事务中按会话 ID、待生成状态、尝试次数及未删除条件更新。手动改名和删除锁定 Session 行，写入后即使旧模型请求仍在返回，其写入条件也已失效。改名、生成标题和删除更新元数据版本，标题变化沿用原会话排序位置。

会话列表、会话详情、历史消息和 Run 的用户访问均使用现有租户、工作区及所有者约束，并过滤软删除。会话后续提交和删除共用行锁。改名与删除复用现有幂等请求记录。Web 经 BFF 校验命令和回执。待生成时侧栏短轮询会话元数据，完成后回到常规列表刷新，分析 Run SSE 独立。

```text
提交首条消息 → Session 和首条消息落库 → 侧栏显示临时标题
                                      ↘ 后台领取 → 文本 LLM → 条件更新 Session.title
改名 → 写 title 和 manual 状态 → 后台更新条件失效
删除 → 检查 Run 终态和清理状态 → 写 deleted_at → 用户读取按 404 处理
```

## 数据库交付

owner 为 `agent/main`，从 `0010` 升至 `0011`。[Alembic 真源](../../../apps/agent/migrations/versions/0011_session_management.py)为 `agent_session` 增加标题状态、领取信息和删除时间。旧标题和历史消息保留。完整和增量 SQL 由 [SQL manifest](../../../apps/agent/db/main/sql/manifest.json)登记。

发布先暂停新任务受理并备份 Agent 库，执行 `pnpm db:migrate -F agent`，再部署 Agent 和 Web，检查两端就绪及会话入口。恢复时将升级前验证过的备份恢复至独立 Agent 库，核对版本和原凭据，配套旧版本应用切换。保留升级后的库，供核对迁移后的新增数据。

## 验证

真实 PostgreSQL 覆盖空库、旧库、原生与 SQL 升级、权限、备份恢复、标题竞态及会话可见性。浏览器覆盖临时标题、完成后标题更新、键盘改名、窄屏删除和刷新读取。模型通道使用项目已有协议模拟端点验证。
