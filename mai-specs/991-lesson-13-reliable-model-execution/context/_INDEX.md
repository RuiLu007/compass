## 关键发现

- 需求来源：2026-11-05 用户要求创建第 013 课的需求脚手架；本次仅初始化 Compass Feature，保持 draft，后续规格与技术设计按需开展。
- 课程范围：[第 13 课单课大纲](../../../../../../lessons/v5/formal/lesson_13_reliable_model_execution/brief/lesson_outline.md)，主题为“建立高并发下可靠的模型执行机制”；对应 [README](../../../../../../lessons/v5/formal/lesson_13_reliable_model_execution/README.md) 与 [manifest](../../../../../../lessons/v5/formal/lesson_13_reliable_model_execution/manifest.yml)。页级大纲状态为 pending，教学内容继续在课程工作区维护。
- 目标：在现有模型接入与执行策略基础上，为 Compass 建立可恢复、可验证、可追踪的模型执行机制，通过故障注入与高并发场景验证 Reliable Executor。
- 执行模型：区分 Logical Call 与 Attempt，明确一次逻辑调用、多次尝试及最终结果的生命周期；技术实现和持久化深度留待设计确定。
- 恢复机制：根据故障类型、幂等性、截止时间与输出可验证性，选择 Retry、Fallback、降级、Schema Validation 或直接失败，明确 Timeout、Deadline 与停止边界。
- 输出契约：覆盖 Structured Output、Schema Validation 与 Output Contract，校验后再将结果交给下游；流式输出区分中间展示与最终提交。
- 前置衔接：[Feature 993](../../993-lesson-11-llm-runtime/BRIEF.md) 提供统一模型接入与管理基础；Feature 992（本地需求资料；不随本节点提交） 已覆盖业务无关 Runtime 可靠执行、同模型多供应商容灾及 JEV 受控降级，第 13 课需复用并细化执行机制。992 当前 Phase 为 draft，实际实施状态在后续设计前核对。
- 职责与兼容：Harness 负责意图与任务选模，Runtime 维护业务无关执行能力；沿用既有模型权限、指定模型契约和凭据保护，保留 Provider 配置、历史调用记录及业务数据。Agent 承担推理执行，Web/BFF 按需提供配置与结果展示，跨 app 通过 HTTP 契约通信。
- 数据与契约约束：遵守 [数据库规范](../../../docs/database-migrations.md)，持久化变更在技术设计中登记 owner、迁移源、版本、SQL、发布及恢复顺序；Agent DTO 与路由作为网络契约生成源。初始化不预设新增表或迁移。
- 验证方向：覆盖可重试与不可重试故障、截止时间耗尽、输出校验失败、流式中断与最终提交、高并发下执行边界和结果一致性；具体负载、指标、故障矩阵与验收条件在后续需求细化中确定。
