# 第 13 课：可靠模型执行的架构取舍

本资料供《企业级Agent工程架构实战营》第 13 课学员阅读，依据课程架构取舍页整理，作为 Feature 991 的需求与设计上下文。下文保留该页的本期选择、暂缓建设事项及取舍理由；具体实现与验收约定见[技术方案](../design/TECH_DESIGN.md)。

本期围绕进程内模型调用，优先保护执行容量、控制故障与费用放大、保证最终结果可用，并让取消能够停止当前调用链。规模扩大与分布式任务所需的治理能力按需扩展。

## 1. 并发与资源保护

### 本期采用

- 进程共享并发闸门。
- 8 个执行、32 个在途。
- 有界等待，超额拒绝。

### 暂缓建设

- RPM / TPM 多维限流。
- 租户公平与优先级调度。
- 分布式配额与自动扩容。

### 取舍理由

先保护单进程容量，规模扩大后统一治理。

## 2. 故障恢复与预算

### 本期采用

- Chat 最多两次尝试。
- 共享 180 秒总期限。
- 明确临时故障才重试。

### 暂缓建设

- 跨模型与供应商切换。
- 熔断与半开探测。
- 检查点与重启续跑。

### 取舍理由

限制故障与费用放大，结果未知时停止恢复。

## 3. 流式输出完整性

### 本期采用

- 流式片段作为预览。
- 校验、收尾、完整结束。
- 成功结果才进入上下文。

### 暂缓建设

- Token 逐条持久化。
- 事件回放与游标续传。
- 断点续生成与输出合并。

### 取舍理由

优先保证结果可用，接受中断后重新提问。

## 4. 取消与资源清理

### 本期采用

- 取消沿当前调用链传播。
- 停止等待与后续重试。
- 资源清理，异常槽位隔离。

### 暂缓建设

- 持久化与跨实例取消。
- 执行代次隔离。
- 工具补偿与子任务级联。

### 取舍理由

适配当前进程内调用，分布式任务按需扩展。
