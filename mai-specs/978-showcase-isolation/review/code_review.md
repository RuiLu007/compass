## 已关闭问题

1. **Checkpoint 通用状态契约遗漏**：RuntimeSession 初版快照缺 verifier 键，持久层接受受控模型结果时失败。已提供空的通用 verifier 状态，计划、真实 SQL 工具预算、Checkpoint 与 Worker 边界恢复专项复验通过。
2. **旧请求回执兼容不足**：仅移除 DTO 字段会在已受理请求重试时提前拒绝。已补内部只读回执入口，按当前 owner、requestId 和历史规范化内容核对；未知请求和内容冲突拒绝，不创建或调度新 Run。真实数据库专项验证原回执和 Run 数量。
3. **测试夹具残留 Retail 依赖**：通用持久测试仍要求旧 Retail 凭据，预算审计还把重放入口当作物理 SQL。已改为普通授权连接和常量 SELECT，在实际 SQL 执行层统计派发，复验确认只读查询实际执行一次。
4. **口径提示不足**：真实模型曾将日渠道汇总记录数解释为支付笔数。已在样本表注释声明汇总粒度，并在通用提示词要求区分记录、业务笔数、无记录与零值；复验回答金额与缺口均正确。

5. **进程内写工具回执缺口**：原 Dispatcher 只为远端执行保存物理回执，进程内写工具缺少同等恢复边界。已按 external_write / unknown 副作用统一记录执行，保留只读状态工具的重建方式。真实数据库测试验证审批后 action 为 applied，重放原调用复用已接受回执且副作用仅发生一次。
