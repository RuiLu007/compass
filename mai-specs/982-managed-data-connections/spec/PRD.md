# 数据连接管理与默认 Retail 接入 PRD

> Feature 982 · standard · 模板 `mai-specs/_templates/PRD.tmpl.md`

[返回需求简报](../BRIEF.md)

## 1. 背景与目标

「数据连接」已有导航，当前是空页。第 15 课的分析流程通过部署环境维护一组 Retail 凭据和工作区绑定，更新连接需要改部署配置。管理员需要在产品中维护当前工作区的连接，分析流程直接使用已保存的配置。

## 2. 用户与业务流程

| 用户           | 任务                                                             |
| -------------- | ---------------------------------------------------------------- |
| 平台管理员     | 进入有数据模块权限的工作区，查看、配置和测试其 Retail 连接。     |
| 分析用户       | 在已授权工作区正常发起经营分析，使用该工作区的 Retail 数据。     |
| 本地环境维护者 | 准备 Retail 发布库和只读账号后，通过既有初始化流程登记默认连接。 |

管理员打开「数据与语义 → 数据连接」，看到当前工作区的数据库连接列表，可分别新增、编辑和测试。保存后可测试已保存配置，页面给出成功或可操作的失败原因。接下来发起的分析使用最新保存的配置。

## 3. 功能需求

| 编号  | 需求                                                                                                                                                                                                                                                        |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 每个工作区可维护多条命名连接，支持 PostgreSQL 和 MySQL。平台管理员可新增、查看和编辑主机、端口、数据库、账号、密码和 SSL 模式。默认 Retail 连接额外维护 Retail 租户 ID。已有密码仅显示配置状态。编辑同一端点、数据库、账号和 SSL 模式时，密码留空保留原值。 |
| FR-02 | 「测试连接」验证所选记录的数据库登录和固定轻量查询。默认 Retail 连接额外验证只读身份、行级权限及目标租户可见性。失败显示安全分类，允许修正后重试。                                                                                                          |
| FR-03 | 本地初始化将准备好的 Retail 发布库和只读账号导入对应工作区，作为其默认 Retail 连接。已存在的 Retail 记录升级后保留配置、凭据和版本。初始化可重跑，保留已有配置。没有默认 Retail 的工作区仍可手工配置。                                                      |
| FR-04 | 具备现有分析权限的用户从分析入口发起新 Run，Retail 工具按已验证的工作区读取默认 Retail 连接。未配置时保留普通 Chat，连接失败时显示现有 Retail 错误。                                                                                                        |

## 4. 页面与交互

```text
数据连接                                      [新增连接]
┌ 连接名称           数据库类型        操作 ───────────┐
│ 本地 Retail        PostgreSQL       [编辑] [测试连接] │
│ 经营数据库         MySQL            [编辑] [测试连接] │
└───────────────────────────────────────────────────────┘
```

沿用模型 Provider 的列表与新增入口。新增时选择引擎，编辑沿用记录的引擎类型。字段有可见标签，窄屏单列。加载、保存、测试分别显示进度。保存冲突时提示重新加载配置。测试反馈与所测试的版本绑定，继续编辑或保存后清除。租户管理员和其他用户可见入口时显示「请联系平台管理员配置此工作区的数据连接」。

## 5. 规则与范围

- 凭据由 Agent 服务端加密保存，接口、页面和日志仅使用安全字段。连接目标由部署允许列表约束。
- Web 校验管理员身份、工作区及数据模块权限。Agent 使用受信任的租户和工作区绑定，查询使用 Retail 受限账号与固定参数化 SQL。
- 本次覆盖 PostgreSQL、MySQL 的多连接管理和连通性测试。现有 Retail 分析使用默认 PostgreSQL 连接，校验兼容的 Retail 发布库。其他连接在管理页独立测试。
- 本地默认数据源选用现有第 15 课兼容发布库。准备工作包括创建有效工作区、准备发布库和受限账号，并为初始化提供私有配置。

## 6. 验收标准

| 编号  | 场景                                 | 判定                                                                                                                                 |
| ----- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| AC-01 | 平台管理员打开工作区数据连接页并保存 | 刷新后配置仍在，密码字段为空且显示已配置。留空修改同一账号配置保留凭据。并发旧版本保存提示冲突。                                     |
| AC-02 | 测试已保存的连接                     | 匹配 Retail 的受限账号返回可用。错误密码、错误 Retail 租户、不可达目标或权限不满足得到安全反馈。                                     |
| AC-03 | 初始化已准备的本地 Retail            | 指定工作区自动得到默认连接。重复初始化保留管理员修改。未提供默认配置时页面展示待配置，普通 Chat 可继续。                             |
| AC-04 | 已绑定工作区运行分析                 | 固定查询读到已绑定 Retail 的真实数据，切换工作区仅使用该工作区自己的连接。原有工作区和只读权限约束继续生效。                         |
| AC-05 | 越权、凭据与目标保护                 | 非平台管理员访问管理 API 被拒绝，缺 CSRF 的保存被拒绝，超出部署允许范围的目标无法保存。HTTP 返回和运行日志不含密码、密文及驱动错误。 |
| AC-06 | 应用库升级和恢复                     | 空库安装和旧库升级可用。既有业务数据保留，运行账号只有所需读写权限，受管 SQL 与迁移一致，备份恢复后连接仍可解密。                    |

### 多连接补充验收

| 编号  | 场景                             | 判定                                                                                           |
| ----- | -------------------------------- | ---------------------------------------------------------------------------------------------- |
| AC-07 | 同一工作区新增 PostgreSQL、MySQL | 两条新连接与默认 Retail 同时显示，刷新后保留。编辑其中一条时，其他连接的版本和凭据保持原值。   |
| AC-08 | 分别测试 PostgreSQL、MySQL       | 两种真实数据库均可通过登录和探测，错误凭据返回安全反馈。猜测其他工作区记录 ID 无法编辑或测试。 |
| AC-09 | 已存在的 Retail 连接升级         | 0005 旧记录迁移为默认 Retail，原版本和密文可用。新建普通连接后，经营分析仍使用原 Retail 数据。 |
