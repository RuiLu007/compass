# 四类经营场景的方法与交付要求

本规格是[主 PRD](PRD.md)的场景扩展。四类场景按用户希望拿到的结果划分。同一个业务主题可以先做问答，再展开分析，最后形成看板或报告。切换场景时，已确认的事实、指标口径和范围可以沿用，研究方法和表达方式随新的交付目标调整。

## 共用原则 · 如何找到适用的指标语义

用户说的通常是业务用语，工作空间里维护的是指标定义。**指标语义召回**要解决的是两者能否对上，以及找到的定义能否用于眼前这个问题。

1. **理解用户在衡量什么。** 从问题和已确认的对话中识别对象、关注的现象、范围与用途。用户可以先描述业务现象，Compass 负责找到可能相关的指标。只问业务规则且无须量化时，可直接使用适用的规则说明。
2. **把候选放回业务语境。** 从当前有权使用的指标释义中，结合业务名称、别称、相关概念和定义寻找候选。判断时看统计对象、适用范围、生效期间、时间粒度、聚合方式和单位。涉及比率或比较时，还要看分母或参照对象。名称相近只是查找线索。
3. **处理会改变答案的歧义。** 定义明确且适用时直接采用。多个定义会产生不同答案时，用业务语言说明差别，请用户选定。找不到适用定义时说明缺什么，已有部分能回答的先回答。用户明确指定的临时算法应标作本次约定，便于和工作空间的正式口径区分。
4. **随用途复核。** 同一问题的追问可沿用已确认的定义。对象、期间、汇总层级或工作空间变化时，重新判断定义是否适用。最终答复只展开影响理解或决策的口径细节。

下列上下文清单描述各类任务通常需要的材料。已确认的信息可以复用，按本次问题补齐必要材料即可。各场景的工作方法供选择和调整，具体提示词由 PromptOps 维护。

## 经营问答 · 把眼前的问题答清楚

**研究方法。** 先辨认用户是在问事实、含义、规则，还是在核对自己的理解。确定什么信息足以回答这一问，再决定是否取数。遇到歧义时，比较不同解释对答案的影响，只追问会改变结果的条件。

**指标语义召回。** 优先找到与问法和对象最贴合的定义。问“是什么意思”时，解释它衡量什么、适用在哪里。问“是多少”时，再核对读数的期间、范围和单位。数值为零、没有记录、数据尚未齐备，分别说明。

**默认上下文。** 当前问题和必要的上一轮指代、所在工作空间适用的指标释义或业务规则。需要查数时再带入已授权读数、范围和数据截至时间。

**回答风格与产物。** 简短、直接，先给用户要的答案，再解释影响理解的条件。交付物是原对话中可以重读的答复。读者应能分清“答案是什么”和“它在什么条件下成立”。

<a id="data-analysis"></a>

## 数据分析 · 让结论经得起比较

**研究方法。** 把用户的疑问转成可以用数据区分的判断，再选比较、分解、趋势、分布或假设检验等适用方法。先观察整体，再沿有解释力的维度查看差异。判断一个解释是否成立时，考虑样本构成、口径变化和其他可能原因。材料只支持描述变化时，结论就停在变化本身。

**指标语义召回。** 从研究问题出发，先找能衡量目标现象的指标，再根据待验证的解释补充相关指标和维度。重点核对比较双方是否覆盖相同的对象、期间和统计粒度。对比例或派生指标，确认分母及聚合条件。口径变化时，优先使用可比范围，并说明这一选择如何影响结论。

**默认上下文。** 待回答的问题、分析对象、主指标释义、可用维度和数据覆盖情况。比较任务补入参照对象，解释性任务按需补入业务事件、替代解释和可用于核查的观察。

**回答风格与产物。** 结论先行，随后给出最能支撑判断的比较，并区分观察、解释与待核实事项。交付物是可复核的分析结果。按问题选择对比表、图或文字，保留读懂结果所需的范围、基准与单位。用户要求导出数据时，CSV 应与答复采用同一范围和口径。

## 看板创建 · 让读者能自己观察和比较

**研究方法。** 先明确看板供谁使用、打开后要判断什么，再决定呈现哪些指标、如何分组、需要哪些比较与筛选。选择视图时考虑读者是要看水平、变化、结构还是差异。用读者最关心的问题检查布局，确认他能从总览找到需要进一步查看的部分。

**指标语义召回。** 从观察目标选出主指标及有助于解释它的维度。检查各视图采用的时间粒度和筛选范围，特别关注汇总到明细、改变分组后指标是否仍有相同含义。比率等指标应按其定义汇总。不同视图有意采用不同范围时，在对应位置标清差别。

**默认上下文。** 目标读者、观察目的、已确认的指标与维度、筛选条件、数据覆盖与截至时间，以及本次希望沿用的已有视图或分析结果。

**回答风格与产物。** 对话中简要说明看板能回答什么、从哪里开始看，并提供打开入口。主要交付物是可从原会话重开的看板。看板本身应标清主题、范围、单位、数据截至时间和缺数状态。读者重开后能看到创建时的读数和筛选。

## 经营报告 · 围绕读者要作的判断组织全文

**研究方法。** 明确读者、用途和核心议题，围绕这些议题选择值得写入的发现。将相关观察串成有主次的论述，说明变化意味着什么、哪些解释仍待核实。报告需要支持决策时，建议应能对应到具体发现，并交代适用条件。篇幅和章节随读者需求及已生效模板调整。

**指标语义召回。** 按报告要表达的关键判断选指标。核对同一指标在摘要、正文、图表和引用材料中的定义与期间。引用目标、预测或历史值作参照时，标明其性质，并核对与实绩的可比条件。来源口径存在差异时，说明采用哪项定义以及对解读的影响。

**默认上下文。** 报告用途、读者、覆盖范围、适用的部门模板、已核对的指标释义和分析发现。按议题补入比较基准、业务背景、重要限制或上次待跟进事项。

**回答风格与产物。** 对话摘要突出读者最需要知道的判断。完整报告应有清晰主线，重要结论有相应事实支撑，脱离聊天记录也能独立阅读。提供打开和下载入口，首版支持 Markdown 下载。摘要、正文与下载稿中的判断、数字和口径应一致。
