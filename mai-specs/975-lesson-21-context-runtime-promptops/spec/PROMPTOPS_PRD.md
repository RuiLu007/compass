# 第 21 课 · PromptOps 产品需求

Feature 975 · 草案 · 负责人 andy · 2026-11-19

平台管理员从 Compass Web 的「管理与治理 → 平台管理 → PromptOps」打开一棵与本地 `prompts/` 对应的文件树。选中文件即可读 Markdown 正文、保存草稿并独立发布。整体发布会留下整库快照。经营人员继续在分析对话中使用经营问答、数据分析、看板创建和经营报告。[主 PRD](PRD.md) · [四类任务的产品定义](SCENARIO_REQUIREMENTS.md) · [打开交互原型](prototype/promptops.html)

## 1. 用户故事 · 只改财务周报的首行

**作为平台管理员，我想单独发布财务周报的提示词，让华东财务部下一份周报直接给出实付额和环比，同时让运营同事继续使用原有的周报格式。**

| 步骤     | 管理员看到或做的事                                                                                                                                      | 业务结果                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 找文件   | 展开 `tasks/business_report/scenes/weekly/`，点击 `finance.md`。右侧显示《财务周报摘要》、当前文件版本和使用位置。同目录的 `report.md` 是通用经营周报。 | 同一个文件在本地与管理页具有相同的相对路径，可以直接按路径查找。                                                          |
| 改正文   | 在右侧将首行要求改为“首行写实付额和较上周变化”，预览 Markdown 后保存草稿。                                                                              | 管理员重新打开仍能继续编辑。此时业务周报沿用已发布正文。                                                                  |
| 单独发布 | 点击“发布此文件”，核对路径、旧版、候选正文和使用位置，填写发布说明并确认。                                                                              | 只有 `finance.md` 从 v1 升至 v2。其他文件的生效版本和待发布草稿各自保留。                                                 |
| 验证     | 华东财务部发起一份新周报。本次发布验收设定本期实付额 120 万元、上期 100 万元，预期摘要首行为“实付额 120 万元｜较上周 +20%”。                            | 发布后 60 秒内新受理的匹配任务使用 v2。发布前已受理的周报、华东运营部的通用周报和同部门的数据分析任务保持各自的文件版本。 |
| 恢复     | 从此文件的历史打开 v1，将正文恢复为草稿，再单独发布。                                                                                                   | 该文件生成 v3，正文与 v1 一致。v2 及其发布记录仍可查阅。                                                                  |

## 2. 一棵对应本地的文件树

树根是本地集中管理的 `prompts/`，文件的完整相对路径是管理、版本和代码引用共同使用的标识。相同文件名可以出现在不同目录。每份系统提示词、场景模板、共用片段和辅助提示词都有自己的 Markdown 文件。首次上线的盘点覆盖主分析、识别与澄清、查询与工具说明、Skill 片段、子任务、标题、预填提问和最终输出。验收时以实际交付的完整本地清单核对。

| 目录                     | 管理员如何查找                                                               |
| ------------------------ | ---------------------------------------------------------------------------- |
| `tasks/business_qa/`     | 经营问答的 `system.md` 与 `scenes/metric_lookup/answer.md` 等场景文件。      |
| `tasks/data_analysis/`   | 数据分析的任务指令，以及 `scenes/period_comparison/` 下的周期对比模板。      |
| `tasks/dashboard/`       | 看板创建的任务指令，以及 `scenes/channel_overview/` 下的渠道概览布局提示词。 |
| `tasks/business_report/` | 经营报告的任务指令，以及 `scenes/weekly/` 下的通用周报和财务周报。           |
| `shared/`                | 跨任务复用的基础片段、阶段指令、工具说明及 Skill 指令。                      |
| `support/`               | 路由辅助、会话标题、子任务和产品预填提问等后台或入口提示词。                 |

**文件的位置与调用关系分别有明确的用途。** 目录帮助人找到文件。Compass 代码决定给哪一个租户、部门工作空间、任务、场景与阶段装载哪些路径、工具和 Skill。管理页以只读方式说明文件的使用位置。共享片段发布后影响所有引用方。新建文件可保存、发布、进入快照，待代码引用该路径后才参与实际任务。工具和数据权限沿用现有授权。

**首次上线。** 管理员导入随包提供的完整本地目录，核对路径后保存为线上草稿，再整体发布初始版本。线上数据库持久保存文件正文、草稿、发布历史和快照。应用重新部署后继续使用当时的生效版本。

**本地与在线协作。** 再次导入时按相对路径核对正文。相同内容可跳过，新增文件进入自己的目录。本地与在线都改过的文件展示差异，由管理员选择是否采用本地正文作为新草稿。导入保留线上生效版本与本次目录未包含的文件。线上新建的文件标为“线上新增”，可下载 Markdown 放回同一相对路径。[原型所用的本地目录](prototype/local/prompts/)

## 3. 文件版本与整库快照

| 操作                       | 管理员确认的内容                                                                                       | 生效结果                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 保存文件草稿               | 当前路径、Markdown 正文，模板可试填期间、单位等变量。                                                  | 一份文件可有一份待发布草稿。保存后可刷新重开。                                                                                   |
| 发布此文件                 | 只查看该文件由哪个版本变为哪个版本、修改的正文、只读使用位置与发布说明。                               | 本文件生成自己的不可变版本号。其他文件和既有快照都保持原记录。                                                                   |
| 整体发布                   | 确认所有已保存草稿、各自将生成的版本、前次快照之后已单独发布的变化，并填写说明。未保存的编辑另行提示。 | 所有候选一次生效，生成一个含**全部生效文件路径与确切版本**的快照。未改文件沿用原版本号。任一候选无法发布时整批保留原状。         |
| 仅有单文件发布后的整体发布 | 确认此刻的完整生效清单。                                                                               | 可以为当前组合留下新快照，无需为已发布文件重复升版。清单与最新快照相同且没有变更时直接查看已有快照。                             |
| 查看或恢复快照             | 查看快照编号、说明、操作者、时间，点开任一条目读取当时的正文。恢复前确认涉及的文件与版本。             | 一次恢复整份生效清单，并留下新的恢复快照。后来新增的文件保留历史，退出生效清单。已有草稿保留，基线发生变化的草稿须核对后再发布。 |

每次任务受理时固定当时生效的文件版本组合。管理员可在整体发布后继续单独升级任何一个文件。此时最近的快照仍记录整体发布当天的组合，线上任务采用随后生效的新组合。查看旧报告或继续已受理任务时使用当时的内容。

## 4. 界面与反馈

- **文件库。** 左侧按原路径逐级展开，支持搜索路径、文件名或标题。选中文件后，右侧显示路径、使用位置、草稿与生效版本，可在 Markdown 预览、源码编辑和本文件的版本历史之间切换。预览渲染标题、列表、引用、表格及代码块。模板变量保留原名，可单独试填样例。
- **新建与编辑。** 在树中选定目录后点击“新建提示词”，填写目录、文件名和正文。新场景可随文件创建子目录。路径重名时定位到已有文件或修改名称。空正文、未支持的变量在发布时提示具体文件。两人改同一份正文时保留后提交者的输入，先比较线上最新内容再决定继续保存。
- **发布与回看。** “发布此文件”位于正文区。“整体发布”和“整库快照”属于库级操作。发布前可取消，成功后明确显示文件版本或快照编号。草稿、单文件生效与最近快照用文字区分。
- **权限与窄屏。** 平台管理员可管理文件、发布和恢复。租户管理员和普通成员通过受权的业务功能使用结果。窄屏可收起文件树以阅读或编辑正文，键盘可展开目录、选择文件、确认发布和取消弹窗。

静态原型内置完整的教学样例，直接打开即可使用，也可选择本地 `prompts/` 目录试导入。原型数据保存在当前浏览器，真实业务效果在 Compass 对话中验收。[打开 PromptOps](prototype/promptops.html)

## 5. 业务验收

| 编号                     | 验收场景与结果                                                                                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-04 单文件改版         | 财务周报与通用周报各改一份草稿。只发布财务文件，核对 v1 → v2。通用文件仍为 v1，草稿仍可编辑，旧版财务正文可单独恢复。                                                                  |
| AC-05 权限与并发         | 以平台管理员、非管理员访问并尝试发布，分别得到管理入口或受限反馈。两个编辑者改同一文件会看到冲突并保留输入。分别改不同文件可独立保存和发布。                                           |
| AC-10 管理交互           | 在桌面、390 像素窄屏和键盘下按目录查找、搜索同名文件、新建及编辑、预览渲染、试填变量和查看历史。检查取消、错误反馈和焦点返回。                                                         |
| AC-12 完整文件树         | 将本地清单与树中的相对路径逐项比较，目录层级、同名文件、正文与文件总数一致。四类任务均有任务指令和场景子目录，公共片段和后台辅助提示词均可打开。                                       |
| AC-14 首发与持久化       | 空库导入后整体发布。刷新或重启后可按路径重开草稿、文件发布记录与快照。重复导入、两端修改或本地遗漏某文件时，已发布内容都可追溯。                                                       |
| AC-15 独立发布与整体快照 | 从 S001 开始单发一个文件，再整体发布另一个草稿。S002 记录两项变化和其余未改文件。只读 S001 仍可打开旧正文。一个无效草稿会阻止整批提交。恢复 S001 后新任务采用恢复的组合。              |
| AC-16 固定调用关系       | 对照华东财务部的经营报告、同部门的数据分析、华东运营部及另一租户的周报。只更新财务周报文件时，只有代码中引用该路径的新任务发生相应变化。新建一份文件后，管理员可查看其“尚未接入”状态。 |
