## 初始化发现（历史记录）

- 需求来源：2026-11-04 用户要求创建第 12 课需求脚手架，在第 11 课基础上完成多模型路由课程目标。本次授权覆盖 Feature 初始化，后续按需编写规格与技术设计。
- 课程关联：[当前课程大纲入口](../../../../../../course/curriculum/README.md)、[V5 正式课总大纲](../../../../../../course/curriculum/v5/course_outline.md)、[第 12 课单课大纲](../../../../../../lessons/v5/formal/lesson_12_multi_model_routing/brief/lesson_outline.md)。第 12 课页级大纲为 pending；本 Feature 以本次用户目标为需求输入，教学材料继续在课程工作区维护。
- 前置基础：[第 11 课 Feature 993](../../993-lesson-11-llm-runtime/BRIEF.md) 已形成统一调用契约、进程内薄 Runtime、Provider 管理与持久化、能力测试、Chat 手动选模和基本调用记录。需求细则见 [993 PRD](../../993-lesson-11-llm-runtime/spec/PRD.md)，实现与待验事项见 [993 实施记录](../../993-lesson-11-llm-runtime/IMPLEMENTATION.md)。
- 承接状态：993 实施记录登记两款 DeepSeek LLM 的真实调用已通过，阿里云决策模型的真实供应商测试后置，Feature Phase 仍为 draft。第 12 课复用既有接入配置与调用能力，具体基线验证在后续实施时执行。
- 逻辑与物理模型分层：业务按逻辑模型和任务需求发起请求，物理模型标识、Provider 及端点由配置映射。沿用已有平台统一管理模型的安排，明确配置变更对后续调用的生效方式。
- 路由选型：比较静态绑定、确定性规则和受控动态策略的收益、风险与维护成本，按 Task Profile 选择满足目标的最简形态，并说明选择理由、适用条件和升级触发条件。动态策略的实现深度在后续规格与选型中明确。
- 能力与任务契约：建立 Capability、Task Profile 与模型能力约束的对应关系，覆盖任务所需的输出格式、工具调用、Thinking、Streaming 等已有能力差异。候选模型需要满足任务约束，并能解释入选、排除与最终选择的原因。
- 效果、成本与稳定性：定义主选、Fallback 与降级策略，以及候选范围、触发条件和停止边界；降级后继续满足任务必需能力及租户约束，无合适候选时返回明确结果。详细恢复执行机制与第 13 课衔接。
- 多租户治理：在现有身份与权限基础上，建立租户模型使用范围、预算约束和区域策略，作用于初次路由、Fallback 与降级全过程；预算口径、超额行为与租户可配置范围留待规格明确。
- 课程实战：当前总纲列出分析、SQL、证据判断、报告生成四类任务，作为路由策略与能力匹配的场景来源；任务 Profile 的演示不扩展为本课交付完整 SQL 执行、报告生成或 Agent Loop。
- 应用与数据归属：[数据库规范](../../../docs/database-migrations.md)规定 Runtime 模型映射、路由策略、租户模型运行约束及路由记录归 Agent/main；Web/main 复用账户、租户、权限和通用审计，Web 承担管理 UI/BFF。跨应用通过 HTTP 契约访问，模型凭据留在服务端。具体迁移对象、版本、SQL 与恢复顺序由技术设计登记。
- 兼容与保留：复用第 11 课 Provider 配置、凭据保护、能力测试与已有授权，保留账号、租户、配置、历史调用记录及演示数据。Chat 手动选模与新增路由策略的关系须明确；规则启用和迁移不得隐式扩大租户模型权限。
- 课程切片：本课形成路由选型、任务匹配、Fallback/降级策略和租户约束闭环；第 13 课承接高并发可靠执行、Attempt/Retry、截止时间与流式最终提交，第 14 课承接完整 Trace/Replay、成本运营与发布治理。本课所需的基础预算约束和路由解释保留在范围内。
- 后续验收方向：用代表性任务验证逻辑模型映射、三类路由形态的适用取舍、能力不匹配、权限/预算/区域限制、主选失败与无合适备选，并检查选择原因可查看、旧配置可继续使用；具体可判定 AC 在后续有效需求来源中维护。
