# PRD：第 12 课两级意图分流与模型路由

> Feature：992 | 状态：review（本期开发与流程验收完成） | 负责人：andy | 更新：2026-11-05

[返回需求简报](../BRIEF.md)

2026-11-05 范围收敛：意图识别只输出一级分类和二级场景，通过字典表提取特征，通过路由契约选择模型，调用现有 LLM Runtime 完成一次推理。JEV 优先实验、Flash LLM 分类兜底继续保留。完整 Harness、Skill/subAgent/workflow 分派留待后续章节；Runtime 可靠性建设留到第 14 课。

推理统一复用现有 `POST /api/web/v1/models/calls`，前端每轮只发送一次请求，服务端完成分类、特征提取、选模和推理。路由规则、分类器角色绑定、门槛和默认值直接写入服务端代码配置，随代码发布；本期不提供路由策略持久化、管理界面或管理API。

## 1. 背景与目标

本需求承接《企业级Agent工程架构实战营》第 11 课的[统一模型接入与调用能力](../../993-lesson-11-llm-runtime/spec/PRD.md)，交付用户问题到正确模型推理的最小闭环。

### 意图分类的核心决策目标

1. **识别业务域，匹配专业分析方法与 Skill。** 不同业务域采用不同分析方法；一级分类与二级场景为后续选择专业 Skill 提供依据。本期完成分类和字典设计，Skill 调用由后续执行层接入。
2. **区分任务复杂度，选择合适的模型。** 需要大量取数、多维关联和归因诊断的任务采用更强的模型；给定完整材料后的直接解读、报告组织和简单问答优先使用 Flash。需要形成新诊断结论的报告按复杂分析处理；具体选模保留既有固定模型与特殊场景契约。

### 1.1 交付目标

1. 使用 JEV 主路及 Flash LLM 兜底识别一级分类、二级场景，返回统一结构。
2. 按分类/场景查字典得到任务类型、难度、响应方式和必需能力，模型不直接生成这些特征。
3. 路由契约结合字典特征与用户模型选择，确定本次推理模型和参数，复用现有 Runtime 完成推理。
4. 展示两级分类、字典特征、选模原因、实际模型与分类/推理用量和耗时。
5. 保留前端静态主模型选择；选择仅约束本次主模型推理，分类器路径独立。

### 1.2 取舍与边界

效果和性能优先，成本节约参与模型选择。JEV优先验证接入与分类流程，效果调优留后续课程；Flash 既是单路基线，也是 JEV 不确定或不可用时的分类兜底。

本期不实现完整 Harness、业务 Skill 选择与执行、subAgent 调度、workflow 编排、工具/SQL执行、任务拆分和多步骤推理。不同分类未来可以对应任一种业务执行方式，本期接口不绑定这些实现，也不预建分派注册表。

Runtime 可靠性留到第 14 课。本期复用已有单次调用、能力校验、取消、时限、错误与用量记录；不新增重试、跨模型生成 Fallback、受控降级、同模型多供应商容灾、并发治理或恢复执行器。分类 JEV → Flash 兜底属于本期路由链。

| ------------ | ------------------------------------ | ----------------------------------------------------------- |

### 2.2 分类与字典契约

模型输出对象严格包含两个字段：

```json
{ "category_id": "business_channel", "scene_id": "SC-01" }
```

字段值示意；实际ID、一级分类与二级场景对应关系由场景字典维护。`scene_id` 必须属于 `category_id`。模型不得返回难度、动作、工具、Skill、模型ID、额外标签或子任务数组作为意图分类结果。JEV协议附带的概率与判断元信息留在分类适配层，用于门槛和兜底，不混入分类对象。

字典项按二级场景维护一级归属、任务类型、难度、响应方式和必需能力；查表后产出特征，特征不是本轮模型预测。版本化路由契约根据这些特征映射模型档位。分类字典变更与路由契约变更分别校验，引用在受理时固定。

本课模型基线为 L1 → Flash，L2/L3 → Pro。难度待定、缺信息、范围外和复合任务映射到明确的澄清/拒绝/范围说明场景；本期不拆分复合任务。受信权限与输入检查在服务端执行，分类结果不授予数据或执行权限。

同句输入可随成功会话上下文命中不同场景；相同场景的特征由当前字典版本确定。需要动态预测新特征时，在后续需求单独扩展分类契约。

### 2.3 样例与流程验收

现有40场景/88题保留为规格素材，线上目录仅导出场景及默认字典特征，不包含问题金标。模型只验两级Intent输出，特征和选模分别确定性验证；旧JEV降级、业务分派、多步骤及Runtime恢复不进入本期验收。

本期不做效果调优，不要求正式留出集、准确率或性能收益准入。单元/集成/E2E用受控分类答案验证流程和边界；真实模型用少量合成问题验证调用与兜底。效果评测与阈值校准留后续课程。

## 3. 业务流程

```text
用户问题 + 成功上下文 + 主模型选择
  → JEV两级分类 → 校验类型、候选、归属与代码默认门槛
      → 合格：采用
      → 不确定/失败：Flash两级分类兜底 → 同一Schema及归属校验
  → 按一级分类/二级场景查字典提取特征
  → 按路由契约选模型（静态主模型覆盖自动选模结果）
  → 通用调用请求 → 现有LLM Runtime单次推理
  → 正确的响应结构、回答、分类/路由解释及分项消耗
```

两路均失败时停止并返回分类错误；Flash返回字典登记的“待澄清/未识别”场景时按字典响应方式处理，不补造场景。已有取消、撤权、输入限制和时限约束持续有效。推理模型失败直接返回现有错误，本期不自动换模型重发。

沿用现有[模型页面](../../../apps/web/src/features/models/pages.tsx)、[分析输入框](../../../apps/web/src/components/analysis-composer.tsx)、公共弹窗与样式。平台Provider配置和测试继续复用；本期沿用统一Chat发送入口，路由配置在代码中维护。分类专用测试通过本地脚本/测试函数运行；不新增路由测试页、策略编辑器、兼容组管理或Runtime可靠性配置页。

```text
分析Chat
[主模型：指定模型 / 系统优化] [发送 / 停止]
分类：一级分类 / 二级场景
特征：任务类型 / 难度

[查看选择原因：字典版本、契约版本、命中规则、分类来源与分项消耗]
```

响应对象分层：intent仅为两级分类；features来自字典；routing给出选模结果和契约；result为现有Runtime调用结果；metrics记录JEV/Flash分类及本次推理。classifier来源、置信门槛及兜底原因放外层元信息。

生成中不能切换模式，停止同时取消当前分类或推理；模式/主模型切换沿用新上下文确认。成功回答参与下一轮上下文，失败/不完整内容不加入。加载/空/错误、权限撤回、键盘焦点和375/768/1440px适配沿用现有要求。
