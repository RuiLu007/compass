## 1. 背景与目标

管理层、财务、市场与门店用同一个「销售额」提问时，可能分别需要成交 GMV、净销售额、营销归因成交额或授权门店成交额。指标的时间字段、去退款规则、聚合粒度和组织范围会改变结果。Compass 要让团队能盘点、定义、审查并发布这些口径，让 Agent 按当前用户权限和发布版本执行查询，并将口径显示在分析结果中。

首期至少发布销售、营销、库存三个业务域。财务定义用于验证同名冲突，财务域可随素材成熟扩展。量化目标及计算方法统一见 AC-10，目标值待实施后实测。

## 2. 用户与场景

| 用户         | 场景                         | 所需能力                                       |
| ------------ | ---------------------------- | ---------------------------------------------- |
| 语义维护者   | 指标盘点、接入报表或修订公式 | 登记来源，发现候选、比较差异、提交审批         |
| 业务专家     | 指标进入评审                 | 确认适用对象、业务含义与异常规则               |
| 数据负责人   | 业务通过后                   | 验证可执行性、权限及影响，批准发布候选         |
| 发布负责人   | 已批准版本拟生效             | 选择全量或灰度对象，跟踪发布、回滚及历史       |
| 授权经营用户 | 从分析 Chat 提问             | 查询、对比、下钻，确认歧义，查看口径和数据范围 |
| 评测负责人   | 版本发出前及上线后           | 用固定样本复测，处理错误反馈与修订建议         |

## 3. 业务流程

1. 维护者按业务域盘点已有口径，录入 Schema、历史 SQL、BI 指标清单、报表及业务文档。AI 生成候选和审查建议，维护者编辑后提交。
2. 业务专家确认含义，数据负责人验证计算与授权。退回时显示原因，修订后重新评审。已批准候选展示受影响对象，发布负责人选定灰度范围或全量发布，可回切仍有效的历史版本。
3. 用户提问后，Compass 在当前作用域解析指标、维度、时间、过滤和组织范围。唯一合法口径可执行，多个同等候选时提示选择，越权或无对应定义时给出可操作反馈。工具返回数值及版本、口径和范围，分析与报告可继续引用该结果。
4. 评测覆盖同问不同角色、多指标、多维度及跨域报告。线上错误进入反馈队列，AI 可生成修订提议，修订沿用同一评审链。

## 4. 功能需求

| 编号  | 能力              | 行为与可见结果                                                                                                                                                                                           |
| ----- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 盘点与优先级      | 按域汇总现有名称、口径、负责人、适用范围、来源与缺口。对冲突、重复、缺失标注原因，记录首期优先级及后续范围。                                                                                             |
| FR-02 | Metric Registry   | 管理域、指标、维度、实体和关联。指标可登记名称、别名、公式、聚合、粒度、默认时间字段、时区/日历、过滤、币种/单位、允许维度、数据源、依赖、血缘、版本与状态。支持按租户、工作区、部门、岗位配置适用规则。 |
| FR-03 | AI 生成           | 从已授权 Schema、SQL、报表、BI 指标清单与业务规则中发现候选指标和维度，建议定义、公式、别名和依赖。每条关键建议显示来源位置、置信度与缺失项。支持人工编辑或丢弃。                                        |
| FR-04 | AI 审查           | 识别同名冲突、重复、公式错误、无效维度、缺失血缘、旧口径及权限风险。显示检测类型、影响字段、依据和修正建议。规则错误阻断提交或发布，疑似问题交人工判断。                                                 |
| FR-05 | HITL 审批         | 维护者提交后由业务专家、数据负责人依次评审。按工作区配置审批成员。待审人可批准或附原因退回，系统记录版本、意见和时间。修订使旧审批失效。                                                                 |
| FR-06 | 版本与发布        | 提供版本差异、变更记录、影响预览、灰度发布、扩大范围及显式回滚。影响包含系统已登记的依赖指标、查询、报表。无法定位的外部关联显示覆盖缺口。审批与灰度只影响指定候选和指定范围。                           |
| FR-07 | Semantic Resolver | 基于已发布定义、有效权限和提问解析 Metric ID、口径版本、维度、时间和过滤条件。可请求用户选择合法候选。无匹配、不可用维度及数据权限变化有明确处理结果。                                                   |
| FR-08 | 查询与报告        | 支持指标查询、同环比或分组对比、沿允许维度下钻。结果展示单位、时间窗、过滤范围及口径版本。多指标跨域分析按共同粒度和一致时间窗比较，可生成带结果引用的报告。                                             |
| FR-09 | 评估及持续优化    | 针对固定样本计算六项验收指标，记录失败类别和版本。授权人员可以反馈错误、查看建议、创建修订候选并跟踪复评。                                                                                               |

## 5. 界面与交互

沿用 Compass 的「数据与语义 → 指标口径」导航及分析 Chat。以下为拟议线框，管理页的操作权限独立于查看权限。

```text
指标口径
[业务域筛选] [状态筛选] [搜索]               [登记来源] [生成候选]
指标列表                            详情：定义 / 依据 / 依赖 / 版本
销售额 · 销售 · 已发布              当前口径、变更差异、影响范围
净销售额 · 销售 · 待业务评审        [提交评审] [批准或退回] [发布或回滚]
```

详情保留草稿编辑和候选预览。提交、发布和回滚确认时展示目标版本及人群。提交期间禁用重复操作，失败保留已填内容并提示刷新或重试。空列表引导登记来源，未获权限的用户只看到允许访问的对象。键盘可操作筛选和确认，焦点关闭时回到触发控件。

| 触发                     | 拟议文案                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| 同名且可选               | 找到多个「{指标名}」口径，请选择要查询的口径。                     |
| 缺少可执行定义           | 当前范围没有可查询的「{指标名}」口径。请调整问题或联系指标维护者。 |
| 当前版本变化导致发布冲突 | 发布状态已更新。请刷新并重新确认发布范围。                         |
| 影响范围不完整           | 已列出系统内登记的依赖。请补充核对外部报表与查询。                 |

## 6. 业务规则

- **BR-01 作用域。** 同名可关联不同稳定指标 ID。可执行范围由租户、工作区、授权数据和发布规则共同决定。查询里的部门或岗位仅用于表达意图，服务端从授权身份获取实际范围。同名候选在相同优先级冲突时澄清。可展现的候选也必须通过访问检查。
- **BR-02 计算口径。** 采用定义绑定的业务时间与统计粒度，计算区间使用左闭右开。库存快照只能按对应时点策略汇总。比率从同一范围内的分子分母重新计算，分母为零标为不可计算。跨域先对齐时间、单位、维度和粒度。无数据与数值零分别呈现。
- **BR-03 审批与发布。** 作者、业务确认人和数据审批人按职责分离，两次审批须来自不同人员。审批绑定候选内容版本。发布与回滚留存操作者、理由、影响范围和前后版本。灰度面向明确的授权工作区或组织人群，其他人沿用原发布版本。
- **BR-04 版本一致性。** 单次运行固定生效发布；恢复、重试及每次工具查询复核当前权限。权限撤销、发布撤回或来源停用后，拒绝后续计算及失效结果交付。回滚按历史定义生成新的发布事件。
- **BR-05 数据保护。** AI 只处理获授权来源，不向模型传入连接凭据或完整敏感样本。权限不足、定义非法或不可安全执行时不发起查询。审计、评测及报告按各自访问权限展示。

## 7. 交付范围与依赖

六组任务由 FR-01 至 FR-09 覆盖。首期用 Compass 现有受管连接与零售合成数据，对 BI、历史报表和文档以授权快照或输入材料完成盘点。首期通过分析 Chat 交付报告，查询及报表影响分析覆盖有登记引用的资产。完整外部平台自动同步和通用跨数据源联邦计算列为后续能力。

| AC-06 | 用不同租户、部门、岗位提出「本月销售额」，加入歧义和越权场景         | 返回已配置口径或澄清；越权身份看不到候选或数据，角色声明无法扩大权限                     | FR-07       |
| AC-07 | 执行当前期、对比、下钻和跨域分析，加入重复明细、零分母、快照与空结果 | 数值与独立基准一致，输出可追到口径、版本、范围与单位；无合法对齐时返回原因               | FR-08       |
| AC-08 | 运行中切换默认版本，随后撤回原发布或撤销权限                         | 版本切换不改变在途运行口径；撤回或失权后阻止继续执行及结果交付                           | FR-06/07/08 |
| AC-09 | 反馈一次定义或解析错误，采纳 AI 修订建议后再发布                     | 反馈关联原版本与错误类别；修订走审批；新版可用同一样本复测                               | FR-09       |
| AC-10 | 在固定数据快照、权限样本及冻结评测集上运行下表                       | 六个阈值同时达标；越权测试须全部阻断                                                     | FR-01–09    |

| 目标                      | 度量办法                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| 指标覆盖 ≥ 3 个核心业务域 | 统计拥有已审批、已发布且能在授权范围内执行的指标的业务域数                                           |
| 语义识别准确率 ≥ 95%      | 全部应答样本中，指标、口径、维度和时间窗全部与人工标签吻合的比例；应澄清样本单独分层                 |
| 同名消歧准确率 ≥ 98%      | 同名冲突样本中，以正确 ID/版本、澄清或拒绝命中预期的比例；分租户、部门和岗位报告                     |
| SQL 语义正确率 ≥ 95%      | 应执行样本中，查询范围正确且结果与独立参考 SQL 或黄金结果吻合的比例，执行失败计失败                  |
| 复杂任务成功率 ≥ 90%      | 预定义多步骤案例中，全部必做步骤与报告断言通过的比例，包含跨域及多维度例                             |
| 治理效率提升 ≥ 50%        | 对等复杂度、相同质量门槛下，创建与审查合计人工作业分钟数降低比例，以人工全流程为基线，计入改稿与复审 |

评测负责人在调优前冻结分层样本、分母、独立预期、容差和计时脚本。初版样本目标为识别 100、消歧 100、可执行查询 100、复杂任务 20、治理对照 12 对；样本可在冻结前按素材覆盖调整，阈值保持原图约定。保留原始计数和失败案例，区分未执行与未达标。

## 待确认事项

首批真实部门、岗位、灰度人群与财务口径由业务负责人在接入时确认。设计和本地验收使用合成身份和 Contoso 教学数据。正式运行前须确认每个业务域的授权连接、归属和指标责任人。
