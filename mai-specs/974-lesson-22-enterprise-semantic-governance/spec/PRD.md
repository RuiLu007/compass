## 1. 背景与目标

管理层、财务、市场与门店用同一个「销售额」提问时，可能分别需要成交 GMV、净销售额、营销归因成交额或授权门店成交额。指标的时间字段、去退款规则、聚合粒度和组织范围会改变结果。Compass 要让团队能盘点、定义、审查并发布这些口径，让 Agent 按当前用户权限和发布版本执行查询，并将口径显示在分析结果中。

首期至少发布销售、营销、库存三个业务域。财务定义用于验证同名冲突，财务域可随素材成熟扩展。量化目标及计算方法统一见 AC-10，目标值待实施后实测。

**需求顺序。** 先按企业语义内容专项需求盘点术语与别名、指标定义、实体与关系、可信执行资产。由业务专家和数据负责人共同核对字段、业务时间、依赖、作用域及数据来源。只有能说明来源并通过验证的定义，才能用作正式指标。内容清单和示例口径在专项文档维护，管理、运行与交互的验收统一在本文维护。

**当前产品起点。** Compass 已有「数据与语义 → 指标口径」导航占位、受管只读查询、可恢复的 Chat 与人工确认、Context Runtime 和 PromptOps。现有文件型口径字典可按租户、工作区、来源和有效期匹配指标。第 22 课需要把正式定义、版本与审批落入 PostgreSQL，并把按权发现、前端选口径与保存指标草稿接入上述入口。

## 2. 用户与场景

| 用户         | 场景                         | 所需能力                                               |
| ------------ | ---------------------------- | ------------------------------------------------------ |
| 语义维护者   | 指标盘点、接入报表或修订公式 | 登记来源，发现候选、比较差异、提交审批                 |
| 业务专家     | 指标进入评审                 | 确认适用对象、业务含义与异常规则                       |
| 数据负责人   | 业务通过后                   | 验证可执行性、权限及影响，批准发布候选                 |
| 发布负责人   | 已批准版本拟生效             | 选择全量或灰度对象，跟踪发布、回滚及历史               |
| 授权经营用户 | 从分析 Chat 提问             | 查询、对比、下钻，选择口径，确认临时结果，提出保存候选 |
| 评测负责人   | 版本发出前及上线后           | 用固定样本复测，处理错误反馈与修订建议                 |

有草稿创建权限的用户可以建立个人指标，默认本人维护、发布后仅本人使用。组织指标由对应管理员或获委派的维护者管理。使用指标准入与计算所需的数据访问权分别校验。各身份的权限见 §6.1。

## 3. 业务流程

1. 维护者按业务域盘点已有口径，录入 Schema、历史 SQL、BI 指标清单、报表及业务文档。AI 生成候选和审查建议，维护者编辑后提交。
2. 业务专家确认含义，数据负责人验证计算与授权。退回时显示原因，修订后重新评审。已批准候选展示受影响对象，发布负责人选定灰度范围或全量发布，可回切仍有效的历史版本。
3. 经营用户问「上月销售额是多少」。Agent 从当前可用的术语和指标摘要开始，依问题检索并核对口径。销售工作区配置了唯一默认口径时，结果标注「支付 GMV」、期间、范围和版本。若用户同时有权查询成交额与净额两种口径，且当前表述和默认规则无法区分，Chat 暂停该项执行，请用户在原轮次选择。选择成功后继续此前的对比或报告任务。
4. 评测覆盖同问不同角色、多指标、多维度及跨域报告。线上错误进入反馈队列，AI 可生成修订提议，修订沿用同一评审链。
5. 缺少正式口径时，用户可在授权的连接上做开放查询。用户确认临时结果后，Agent 可对值得复用的计算发出保存邀请。用户也可在同一会话下一轮提出「把刚才按渠道算的净额存成指标」。两种入口都先展示可编辑定义，由用户确认保存到有权维护的范围，再沿既有治理流程送审。

## 4. 功能需求

| 编号  | 能力                 | 行为与可见结果                                                                                                                                                                                           |
| ----- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 盘点与优先级         | 按域汇总现有名称、口径、负责人、适用范围、来源与缺口。对冲突、重复、缺失标注原因，记录首期优先级及后续范围。                                                                                             |

| FR-03 | AI 生成              | 从已授权 Schema、SQL、报表、BI 指标清单与业务规则中发现候选指标和维度，建议定义、公式、别名和依赖。每条关键建议显示来源位置、置信度与缺失项。支持人工编辑或丢弃。                                        |
| FR-04 | AI 审查              | 识别同名冲突、重复、公式错误、无效维度、缺失血缘、旧口径及权限风险。显示检测类型、影响字段、依据和修正建议。规则错误阻断提交或发布，疑似问题交人工判断。                                                 |
| FR-05 | HITL 审批            | 维护者提交后由业务专家、数据负责人依次评审。按工作区配置审批成员。待审人可批准或附原因退回，系统记录版本、意见和时间。修订使旧审批失效。                                                                 |
| FR-06 | 版本与发布           | 提供版本差异、变更记录、影响预览、灰度发布、扩大范围及显式回滚。影响包含系统已登记的依赖指标、查询、报表。无法定位的外部关联显示覆盖缺口。审批与灰度只影响指定候选和指定范围。                           |
| FR-07 | Semantic Resolver    | 基于已发布定义、有效权限和提问解析 Metric ID、口径版本、维度、时间和过滤条件。可请求用户选择合法候选。无匹配、不可用维度及数据权限变化有明确处理结果。                                                   |
| FR-08 | 查询与报告           | 支持指标查询、同环比或分组对比、沿允许维度下钻。结果展示单位、业务时间窗、数据可见截止、过滤范围及口径版本。多指标跨域分析按共同粒度和一致时间窗比较，可生成带结果引用的报告。                           |
| FR-09 | 评估及持续优化       | 针对固定样本计算五项效果指标，记录失败类别和版本。授权人员可以反馈错误、查看建议、创建修订候选并跟踪复评。                                                                                               |
| FR-10 | 平台指标定义与共享   | 在指标口径页手动新建、从可见定义派生、编辑草稿、校验和提交。可按域和归属筛选。分别展示个人、部门、租户或平台的维护归属及发布后的使用范围，列出创建者、最近编辑者和生效版本。                             |
| FR-11 | 默认上下文与动态发现 | 在模型运行开始时提供少量已发布且有权使用的术语或指标摘要。模型可按需搜索、读取定义、继续检索或澄清。用已发布的系统提示词约定这些行为，后续可用 Skill 补充业务域指导。                                    |
| FR-12 | Chat 口径选择        | 当多个合法口径仍无法区分时，原轮次暂停。前端展示差异、接受选择或取消，服务端复核后持久化决定，再继续原任务。                                                                                             |
| FR-13 | 将开放查询沉淀为指标 | 支持用户确认查询结果后由模型判断是否提示保存，以及用户跨轮明确要求保存。两条路径共用来源提取、查重、范围选择、用户确认及草稿回执。                                                                       |

## 5. 界面与交互

[打开高保真交互原型](METRIC_WORKSPACE.html)。左侧可在指标口径管理、Chat 创建草稿、修改口径、选择销售额口径四个场景间切换。确认后写入的演示草稿可在管理页查看，审批、发布和真实取数沿用本文的实施要求。

### 5.1 「数据与语义 → 指标口径」

拟将现有占位页接为指标维护入口。列表、详情、编辑与 Chat 共用同一份定义和权限判定。没有管理权限的经营用户可通过 Chat 查看对其公开的定义。页面沿用 Compass 的[界面样式与状态约定](../../../docs/ui-style-guide.md)。

```text
指标口径
[业务域] [归属范围] [发布状态] [搜索]          [新建指标] [登记来源] [生成候选]
指标列表                              详情    定义 / 依据 / 依赖 / 版本
订单数      全局预置    已发布          名称、适用范围、负责人、生效版本、可用连接状态
销售额      销售部共享  草稿            [编辑草稿] [校验口径] [提交评审]
```

- **填定义。** 新建时分别设置「维护归属」和「发布后谁可用」，默认值分别为「我」和「仅我」。只有具备相应授权时才能改选组织归属或分享给更大范围。录入名称、别名、适用场景、负责人、公式、归集时间与粒度、单位、过滤条件、允许下钻的维度和执行绑定。选取实体与字段时只返回已授权来源。未补齐来源、粒度或校验的条目可存草稿，不能送审发布。
- **看差异。** 输入同名或已有别名时列出可见候选的定义与范围。用户可打开现有指标，或说明业务差异后创建独立口径。部门要调整公共口径时，可从可见定义派生独立指标，保留来源版本。公共原件由其归属范围维护。
- **修订已有指标。** 维护者打开已发布资产时，页面显示「创建修订」。已有可编辑修订时显示「继续编辑草稿」。原发布版照常服务，修订通过审批并发布后生效。仅有使用权的用户看已发布定义，无草稿入口；若具备创建权，可以派生独立指标。
- **审阅与恢复。** 校验在出错字段旁显示原因。提交、发布和回滚前展示目标版本和受影响人群。请求期间阻止重复提交，失败保留输入。过期版本要求刷新核对。空列表引导首次创建或搜索。窄屏表单单列、候选卡换行。键盘可选择选项并确认，弹层关闭后焦点回到触发控件。

### 5.2 Chat 选择口径

以同时有权执行销售和财务两种口径的用户为例。选择卡只包含当前运行通过权限、发布版本和连接绑定检查的可执行候选。仅有阅读权限的公共定义可在定义查询中查看，无权来源的名称、数量和字段保持隐藏。卡片显示可读名称、所属域与范围、关键计算差异、采用的业务日期和生效版本。

```text
找到多个「销售额」口径，请选择本次查询的口径。
○ 支付 GMV  · 销售部  · 按支付日统计已支付金额
○ 确认收入  · 财务部  · 按确认日统计已确认收入
[选择并继续]  [取消本次查询]
```

用户须主动选定一项。「选择并继续」回传本次候选标识。当前 Run 停在原问题。刷新或重连可看到同一待选项。已处理的卡片显示选择及结果。重复点击仅消费一次。若权限、版本或候选有效性变化，刷新可选项。无合法候选时结束受影响的查询。用户选择只用于本次请求，不修改部门默认值。多指标比较已明确指定两个指标时，分别解析执行。

### 5.3 Chat 保存指标草稿

1. **主动邀请。** 开放查询以「临时查询」展示计算口径和适用条件。用户点击「确认结果」或在同会话明确肯定对应结果后，模型判断该计算是否可重复使用、是否有可追溯的来源、是否已有等价指标、用户是否能建草稿。命中条件时可显示「将这次计算保存为指标？」。临时明细导出、明显一次性计算、已存在等价指标、查询失败或用户未确认的结果无需发出邀请。「暂不保存」会保留分析结果，并停止对同一结果的主动提醒。
2. **用户要求。** 后续轮次明确提出保存时，允许直接进入预览，无需先收到邀请。按同一会话的已完成查询回执定位用户所指的计算。「刚才那个」可能对应多项时先列出可见的结果名称和时间请用户选定。遇到过期、无权或无法还原的来源，提示重查或补齐字段。
3. **提取并预览。** 从原始问题、被选中的查询回执及执行计划提取建议名称、业务含义、可复用公式、业务时间、统计粒度、单位、维度和来源。把「上个月」「华东」等本次输入单列为参数样例。若它们确实属于固定业务定义，由用户在预览中确认。展示缺失信息和潜在重复项，允许修改名称、定义和负责人；新建时显示维护归属，分享选项列出当前操作者获准的发布使用范围。修订已有指标时保留原归属。模型生成的 SQL 和数据行均不能直接成为正式执行绑定。
4. **确认写入。** 只有用户点击「确认保存草稿」才创建指标草稿。取消、关闭、失败或缺少写权限时可继续查看原结果。网络重试和重连应返回同一草稿。草稿回执链接到指标口径页，后续校验、提交、双人审批和发布沿用管理流程。保存时如发现同范围等价定义，提示查看现有指标。用户在 Chat 明确提出修订时，先校验当前资产的维护权，再预览与现版的差异。已有可编辑草稿时继续该修订，确认后保存。只有使用权的用户可以查看已发布版或在有创建权时另建独立草稿。

| 触发                               | 拟议文案                                                             |
| ---------------------------------- | -------------------------------------------------------------------- |
| 当前无正式口径且用户有开放查询权限 | 当前没有可用的正式口径。可以调整问题，或使用授权数据做一次临时查询。 |
| 缺少执行权限或数据绑定             | 当前范围没有可执行的口径。请调整问题或联系指标维护者。               |
| 当前版本变化导致发布冲突           | 发布状态已更新。请刷新并重新确认发布范围。                           |
| 影响范围不完整                     | 已列出系统内登记的依赖。请补充核对外部报表与查询。                   |
| 澄清期间候选失效                   | 可选口径已更新，请重新选择。                                         |
| 跨轮引用不清                       | 你想保存哪一次计算？请选择要提取的结果。                             |
| 草稿写入成功                       | 「{指标名}」已保存为草稿。[查看草稿]                                 |

## 6. 业务规则

- **BR-01 作用域。** 同名可关联不同稳定指标 ID。可执行范围由租户、工作区、授权数据和发布规则共同决定。查询里的部门或岗位仅用于表达意图，服务端从授权身份获取实际范围。同名候选在相同优先级冲突时澄清。可展现的候选也必须通过访问检查。
- **BR-02 计算口径。** 采用定义绑定的业务时间与统计粒度，计算区间使用左闭右开。库存快照只能按对应时点策略汇总。比率从同一范围内的分子分母重新计算，分母为零标为不可计算。跨域先对齐时间、单位、维度和粒度。无数据与数值零分别呈现。
- **BR-03 审批与发布。** 作者、业务确认人和数据审批人按职责分离，两次审批须来自不同人员。审批绑定候选内容版本。发布与回滚留存操作者、理由、影响范围和前后版本。灰度面向明确的授权工作区或组织人群，其他人沿用原发布版本。
- **BR-04 版本一致性。** 单次运行固定生效发布。恢复、重试及每次工具查询复核当前权限。权限撤销、发布撤回或来源停用后，拒绝后续计算及失效结果交付。回滚按历史定义生成新的发布事件。
- **BR-05 数据保护。** AI 只处理获授权来源，不向模型传入连接凭据或完整敏感样本。权限不足、定义非法或不可安全执行时不发起查询。审计、评测及报告按各自访问权限展示。

### 6.1 谁可以看、用和维护指标

每个指标分别记录**维护归属**和**发布后的使用范围**。前者决定谁能改定义、建修订、改共享设置和提交；后者决定谁能发现、阅读已发布版本，以及在数据权限允许时查询。同一归属可以对应不同使用范围，例如个人指标分享给销售部后仍由本人维护。

| 维护归属 | 谁能维护                                                             | 发布后的使用范围                                                                           |
| -------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 个人     | 属于当前租户的本人。具备建草稿权限的用户可从管理页或 Chat 为自己创建 | 默认仅本人。本人有相应分享权限时可选择所在租户内获准的部门或租户范围。接收者只读           |
| 部门     | 对该部门获授权的租户管理员、部门管理员或受委派维护者                 | 按该指标已批准的使用范围和实际部门成员关系开放，可叠加工作区或岗位限制                     |
| 租户     | 本租户有语义管理权的租户管理员                                       | 租户公共指标向该租户成员开放，来源绑定、字段和业务行仍按当前工作区与连接复核               |
| 平台     | 有平台语义管理权的平台管理员可以修订全局预置指标                     | 全局公共定义面向所有已登录租户用户。没有本地绑定的用户可以阅读定义，查询时提示当前不可执行 |

创建者、每次修订的编辑者、维护归属分别记录。部门管理员接手同部门其他人创建的组织指标时保留原创建者与部门归属。租户管理员能维护本租户的租户指标及获授部门指标，管理员身份本身不授予编辑他人个人指标、平台指标或其他租户指标的权限。草稿默认只向有维护权者显示，送审后指定评审者可在审批任务中阅读待审版本。已获使用权的成员在草稿阶段不能发现该草稿，修订中只能使用上次已发布版本。更改发布使用范围须验证当前资产维护权及目标分享权限，重新审批并发布后生效。减小使用范围后，即使保留旧链接或已有会话，也按现行权限复核。

默认发现时先裁剪可见候选，再识别适用业务含义。对确有层级继承关系且已设置默认值的同义口径，优先采用匹配更具体的范围。同级冲突、跨部门意图或关键条件仍未明确时进入 FR-12。无权资产的名称、数量、别名、示例及执行结果均不出现在提示、搜索、澄清或历史回放中。全局共享定义可以描述公式，租户私有连接、字段映射和样例数据另按授权展示。

### 6.2 DataAgent 如何取得答案

对经营分析任务，首个模型步骤提供当前有权访问的核心术语、指标名/ID、口径短释和版本。受上下文预算限制时仅保留与任务相关的摘要，并提供动态检索入口。模型按问题决定使用 `search_semantics` 搜索术语、别名、指标或实体，使用 `get_metric_definition` 核对业务时间、粒度与排除项，使用 `resolve_semantics` 取得可执行方案或澄清。搜索优先精确别名，然后匹配规范化关键词及受支持的文本检索。默认摘要中未出现的指标仍可主动发现。需要数值时用 `query_metric` 取得受控结果。模型不得根据名称、示例值或相似口径代答。唯一合法且参数齐全时可结束检索。没有新线索、预算耗尽或有关键歧义时分别返回未匹配、请补充或请求选择。系统提示词固定这些运行原则，技能可补充域词汇及澄清示例。授权、发布与执行参数由服务端强制校验。

经营用户有三条可区分的取数路径。正式指标通过 Metric Query 解析定义并绑定发布版本。已登记的可信 SQL 仅接受获准参数，可作为正式指标的执行资产并返回版本回执。开放分析通过现有 `database_query` 做授权只读查询，标注临时口径。禁止使用开放查询绕过已拒绝的正式指标或补取被限制的数据。

管理时，`discover_semantic_candidates` 从授权素材或已选查询回执提取候选，`review_semantic_change` 返回校验及修订建议，`submit_semantic_change` 在用户要求送审且具备相应权限时提交指定草稿。保存确认只创建草稿。批准、发布和回滚由相应责任人执行。具体工具入参、返回状态与身份来源见[技术方案](../design/TECH_DESIGN.md)。

## 7. 交付范围与依赖

首期用 Compass 现有受管连接与零售合成数据，对 BI、历史报表和文档以授权快照或输入材料完成盘点。首期通过分析 Chat 交付报告，查询及报表影响分析覆盖有登记引用的资产。完整外部平台自动同步和通用跨数据源联邦计算列为后续能力。

教学验收覆盖两家合成租户、销售/财务/营销部门和销售/营销/库存至少三个核心业务域。指标样例包括支付 GMV、净 GMV、订单数、确认收入、广告投放口径及期末可用库存。对「广告 ROI」要先说明分子及成本规则，区分广告支出回报率（ROAS）与利润 ROI。数据不足时保留为待验证候选。实际物理映射、库存时点、财务时间和已具备的数据条件见[专项需求](SEMANTIC_CONTENT_PRD.md)。

启用数据库语义层的工作区从生效发布读取正式口径，原文件型字典的有效定义可经导入、校验和审批后启用。切换后新任务按新发布取数。切换前的运行按原绑定标识恢复，并重新校验当前授权。授权失败或历史定义不可恢复时说明原因。旧报告的口径来源及临时查询标识保留。

## 待确认事项

首批真实部门、岗位、灰度人群与财务口径由业务负责人在接入时确认。设计和本地验收使用合成身份和 Compass 合成零售教学库。正式运行前须确认每个业务域的授权连接、归属和指标责任人。
