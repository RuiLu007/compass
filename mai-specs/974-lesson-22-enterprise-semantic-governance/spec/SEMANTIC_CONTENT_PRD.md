# 第 22 课｜Compass 企业经营语义内容需求

> 草案 · Profile 为 standard · 负责人为 andy。本文定义第 22 课要登记、解释和计算的经营内容，供业务专家盘点、数据负责人配置绑定、产品与研发验收使用。功能、交互和整体达标条件由[主 PRD](PRD.md)维护，工程结构见[技术方案](../design/TECH_DESIGN.md)。

默认资产的字段映射、Showcase 适用口径和单文件入库 SQL 见[零售语义资产设计](../design/RETAIL_SEMANTIC_ASSETS.md)。

## 1. 本课要交付什么

用户问「上月销售额多少」，Compass 应能说明采用了谁发布的口径、按哪个经营事件归期、算入了什么，以及当前身份能查到哪一部分。为此先建立企业经营词汇表、指标字典、实体关系目录和可信执行绑定清单，再将可用内容提供给指标管理页与分析 Chat。

课程首批需要两个有独立数据的租户（教学库选 101、102），在租户内配置销售、财务、营销三个示例部门，并给库存指标指定业务负责人。最低内容集包括下文六项指标，覆盖销售、营销、库存三个必需域，并使用财务确认收入演示跨部门同名问题。下文 ID、别名和术语指向均为教学预置方案，正式接入时由该作用域负责人确认。课堂上的业务映射需新建，零售库已具备对应事实表。

## 3. 四类语义资产与字段

四类内容共用一套身份和发布规则。每项内容须有稳定业务键、显示名称、业务域、维护归属、创建者、修订编辑者、发布使用范围、来源及其位置、版本、审批状态。名称或别名可重复，引用定位到具体资产与不可变版本。同一租户可另建和公用指标同名的口径。不同含义分配不同资产身份，沿用同一含义的修订才产生新版本。

| 类别           | 定义人必须说明                                                                                                                                                | 给使用者的结果                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 业务术语与别名 | 首选词、解释、语言、同义词/缩写、易混词、适用组织与业务域、候选指标或实体、典型问法和反例                                                                     | 能区分「成交额」「确认收入」「净 GMV」的含义；知道何时需要选口径。纯解释类词条可只关联实体，不能直接执行查询。                  |
| 指标定义       | 稳定键、经济含义、公式/度量、单位、分子分母、事实粒度、聚合、事件时间/时区/日历、过滤、退款等例外、维度白名单、依赖和绑定版本、负责人、来源与治理记录         | 能读懂一个数的含义，解释它能否跨日期、渠道或门店汇总，复现同一版本的结果。                                                      |
| 实体与关系     | 每个实体的业务定义、表和字段映射、粒度、主键、业务时间和可见时间。每条边的方向、两端键、基数、可空性、生效区间、允许的分析方向及扇出风险                      | 检索可找到能回答问题的实体。数据负责人可据此批准安全联结、要求先聚合或拒绝不支持的下钻。                                        |
| 可信执行绑定   | 对应指标/版本，参数化 SQL、已审核视图或受控 API 的定位引用与内容哈希；参数类型、枚举/区间及来源、单位、结果粒度、输出字段、空值与失败语义、所需连接及数据权限 | 查询工具只能以受审版本和已校验参数计算。首期使用教学 PostgreSQL 的参数化绑定。视图/API 接口可登记，实际适配并通过校验后才启用。 |

维度依附实体和字段登记，允许共享（如地区）或限定到单一事实（如库存地点）。度量的时间、单位、过滤、聚合规则随指标版本保存。对象之间登记「术语指向」「指标来自」「依赖指标」「实体关联」「通过绑定执行」等关系，可由数据负责人反查变更影响。

### 首批术语

| 词条及别名                   | 定义及消费规则                                                                                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 销售额 / 成交额              | 跨部门歧义词。按成功支付、扣退款、财务确认三种业务事件分别核对支付 GMV、现金流净 GMV、确认收入。上下文仍有歧义时请用户从可见指标中选择。                       |
| 支付 GMV / 支付成交额        | 成功支付的款项总额，按支付事件归期。失败尝试剔除。问「支付订单数」时另走去重计数定义。                                                                         |
| 净 GMV / 退款后成交额        | 首期选用现金流口径，支付和退款各自归入实际事件发生期。按原支付批次追踪最终退款属于另一种定义。                                                                 |
| 确认收入 / 妥投净收入        | 履约妥投产生正项，受理退货产生负项，按财务入账事件归期。「营收」只有在财务作用域批准后才能作为别名。                                                           |
| 广告投放净回报倍数 / 净 ROAS | 指平台归因净回款除以投放消耗。营销部门可审核「广告 ROI」为本指标的本地别名，卡片与结果始终显示正式名称和公式。也可能指利润 ROI，遇到两种合法解释时让用户选择。 |
| 下单数 / 订单数              | 本课公共口径按下单事件统计创建的订单。已支付订单数、商品件数、订单行数单独表达。                                                                               |
| 可用库存 / 可售未预留件数    | 当前地点、SKU 的可售库存扣除预留。与在途、损坏、隔离和库存估值分开。                                                                                           |
| 地区 / 门店 / 渠道           | 订单按原销售地区、销售门店与销售渠道归属；库存按持货地点，退货可在不同地点受理。实名成员所属部门属于权限上下文。                                               |

## 4. 指标目录与计算约定

以下为发布候选口径。金额源字段使用人民币分，加总后可在输出端换算为元，显示单位随结果返回；件、单和倍数分别显示。日历默认上海时区，时间窗为左闭右开，各事实独立按可见截止时间过滤。具体业务接入可另建资产或版本并注明差异。

| 稳定业务键 / 正式名称                              | 粒度、时间与计算                                                                                                                                                                                                                                                                                                  | 允许维度与边界                                                                                                                                                                                                                           |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sales.order_count` 下单订单数                     | 一行订单，按 `order_header.ordered_at` 在期内计数，每租户每个 `order_id` 一次。取消订单仍有下单事件。                                                                                                                                                                                                             | 渠道、销售地区、销售门店。按商品筛选需判断订单是否含指定商品；跨品类订单数不能直接相加。                                                                                                                                                 |
| `sales.paid_gmv` 支付 GMV                          | 一笔成功支付。选 `payment.status='SUCCEEDED'`，合计 `amount_cent`，教学数据以成功记录的 `attempted_at` 作为支付事件时间。                                                                                                                                                                                         | 可按订单渠道、原销售地区和门店分组。对账数据存在回执延迟时需接入成功入账时间并重审；未取得该字段的生产源不能发布承诺按清算时间统计的定义。                                                                                               |
| `sales.net_gmv` 现金流净 GMV                       | 成功支付额减同期成功退款额。按各自 `attempted_at` 筛选 `payment`、`refund` 后独立合计，`refund.amount_cent` 为正数。历史订单的本期退款可使本期净额为负。                                                                                                                                                          | 同支付 GMV，退款归原订单销售维度。按支付月回溯净额须另订退款观察窗和版本。                                                                                                                                                               |
| `finance.recognized_revenue` 确认收入              | 一笔会计分录。对 `revenue_entry.amount_cent` 按 `recognized_at` 求和，`DELIVERY` 为正项，`RETURN_ACCEPTED` 已带负号。                                                                                                                                                                                             | 经单件商品关联原订单，可按销售地区、渠道、销售门店、SKU/品类分析。入账与支付、退款各有时间边界。                                                                                                                                         |

### 历史时点、报表版本与完整度

每次查询区分所问的**业务期间**与用户在何时可以看到这些数的**数据截至时点 K**。时间戳比较使用同一时区的绝对时刻，已到达的边界包含在内（`available_at <= K`）。数据集发布号、K 和实际采用的报表版本随结果返回。下单数、支付额、净 GMV 和确认收入分别按上表的事件时钟过滤。支付和退款只取 `SUCCEEDED`，按销售维度分析时再沿原订单取值；退款日计算本期现金流净额时，保留原单在上期的退款。完整数据集上没有事实取 0，授权缺失、来源迟到或完整度未知应保留相应状态。

**净 ROAS 的取数顺序。** 教学绑定覆盖有平台归因 feed 的活动。先用租户、平台渠道、活动生效区间与所问日期确定应有的活动日，活动外的日期不计入分子或分母。日期对齐使用 `campaign_attribution_daily.cohort_date = campaign_daily.report_date`。对每个应有活动日执行以下步骤。

1. 选择当前租户、活动、渠道中归因规则为 `PLATFORM_LAST_CLICK_7D`、`model_version='1'` 且在 K 前已可见的归因日行（含 K），取最高 `report_version`。此教学源 v1 观察日在归因日后第 8 天，v2 在第 61 天，实际可见还受入库延迟影响。新版本保留已冻结的归因支付金额并更新累计退款。使用所选行自身的 `coverage_status`，未知时返回未知，禁止回退到较早的已知金额。
2. 消耗按租户、活动、渠道、报表日、地区分别在 K 内取最高可见 `report_version`，再汇总到活动日。教学活动每天投放在计划地区 1–7，数据包的消耗版本为 1，必须查齐七个地区。正式接入按绑定登记的投放计划和对账规则判断应到地区；缺失和已到零消耗分别返回。教学源的 `asset_period_status` 记录商品渠道日报的完整度，广告消耗须独立核对。
3. 所选范围内每个应有活动日均有已知归因与完整消耗，才按总归因净额除以总消耗生成总计；分母为零单列「零消耗」，全窗口无适用活动则显示「无适用活动」。若混有归因缺报、未知或消耗不完整，允许列出已知明细及缺口，总计显示不可计算。明确筛选地区、仅有地区级授权或请求按地区下钻时，拒绝此平台级指标。

**可复核的净 ROAS 样例。** 在诊断数据包的租户 101、活动 30、渠道 3，2025 年 6 月 1 日的七区消耗合计 8,053 分。K 为北京时间 6 月 10 日 00:00 时，归因 v1 已可见，支付 22,795 分、退款 0 分，显示 2.8306 倍。K 为 8 月 2 日 00:00 时，归因 v2 可见，累计退款 6,800 分，显示 1.9862 倍。两个结果使用相同的归因日与消耗，金额不做中间舍入。

**期末库存的取数顺序。** 对本地日期区间 `[D0, D1)`，取 `D1` 前一自然日为期末日 D。教学源在上海时间 23:59:59 生成当天期末快照，诊断包从 2025 年 10 月 1 日开始。以该租户生效的 `assortment.valid_from <= D < valid_to`、授权地点和商品筛出应有地点×SKU 组合并去重。逐组合核对 `snapshot_date=D`、`as_of` 为当日期末且 `available_at <= K`，齐备后汇总 `available_qty`。缺少组合时不回填前日、不拿日中采样补齐，返回缺口并留空完整期末合计。期末尚未到达时返回「未到期末」，早于首个快照日则返回「超出快照覆盖期」。零售包中 101 租户、地点 1、SKU 9 在 2025 年 10 月 1 日的期末可用量为 9 件，`as_of` 为 23:59:59，次日 00:00 才可见；K 相差一秒，结果可分别为「快照尚未到达」和 9 件。

**金额和时间示例。** 一笔含三个单件（80、10、10 元）的 100 元订单在 10 月 31 日成功支付，11 月 1 日妥投确认收入 100 元，11 月 3 日受理部分退货冲减收入 20 元，11 月 4 日成功退款 20 元，假定各期数据齐备。10 月支付 GMV 为 100 元，11 月现金流净 GMV 为 −20 元，11 月确认收入为 80 元。「上月」同时记录用户时区、解析时点和解析后的具体日期；历史重跑保留该窗口和数据截至时点。

**缺数处理。** 成功完成并确认覆盖完整的交易期间可以出现零笔或零金额；迟到、缺报及访问受限分别返回数据状态。退款与订单/支付、报表与活动、成本与权限都核准后才能计算对应口径。库存量映射到基准件，估值还需要金额权限与独立绑定。

## 5. 实体、维度和可用关系

下表给出首发计算能使用的主要路径。除日期日历外，所列零售主数据与事实键均带 `tenant_id`。物理关系含额外一致性键时按受审映射校验。数据负责人需给每条可用于计算的路径指定允许的粒度、裁剪规则和历史时点。

| 出发实体 → 目标              | 关系与键                                                                                                 | 可用条件                                                                                            |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 支付 / 退款 → 订单           | 多对一，分别由 `order_id` 关联订单头；退款有 `payment_id` 指向原支付                                     | 支付与退款分别汇总，禁止把一笔支付按其多笔退款重复计入。对多行订单按 SKU 切分金额需先发布分摊规则。 |
| 收入分录 → 单件 → 订单或 SKU | 多对一，依次使用 `order_unit_id`、`order_id` 或 `sku_id`                                                 | 支持单件口径的收入分析。订单数经明细下钻时按订单去重。                                              |
| SKU → SPU → 品类 / 品牌      | 多对一，使用 `spu_id` 后取 `category_id` 或 `brand_id`；品类有上级键                                     | 商品多运动标签经 `spu_sport` 映射，多标签汇总可能重复；标签分摊未定义时禁用该汇总。                 |
| 原销售地点 / 库存地点 → 网点 | 订单使用可空 `selling_site_id`，快照使用 `site_id`；网点再关联 `org_unit_id`、`geo_id`                   | 门店和仓按 `site_type` 区分。缺销售门店保留未归属，禁止把仓或退货接收地替代销售门店。               |
| 报表 → 活动 / 渠道           | `campaign_id`、`channel_id`。消耗报表有地区，归因报表没有；报告日期分别为 `report_date` 与 `cohort_date` | 先按各自自然键及报表版本挑选可见行，再把消耗聚合到共同粒度；覆盖检查贯穿所选日期。                  |
| 库存快照 → 地点 / SKU        | 每租户、日期、地点、SKU、`as_of` 唯一；地点、商品均多对一                                                | 选定同一期末再汇总。数据可见时点 `available_at` 与快照业务时点 `as_of` 同时参与筛选。               |

对实体和维度的词条也提供简单反例，例如「门店销售额」与「从该门店发货的金额」。跨域比较先确定共同粒度、窗口、金额单位和可见范围，再使用两个独立受控结果；无法对齐时展示各自口径和停止合并的原因。

## 6. 公共口径、部门口径与运行时内容

内容卡分别标识「谁负责维护」与「发布后谁可用」。以下为四种教学配置。详细角色与审批规则由主 PRD 的 §6.1 维护。

| 维护归属   | 发布使用范围                                         | 使用示例                                                                                       |
| ---------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 个人       | 默认仅本人。若本人具有分享权限，可选本租户内获准范围 | 101 的小李建立个人净额口径，确认分享给销售部并发布后，销售同事可查询正式版。草稿仍由小李维护   |
| 101 销售部 | 本部门，按需附加岗位或工作区限制                     | 已获委派的销售维护者修订同事创建的支付 GMV，保留创建者与销售部归属。101 财务可维护「确认收入」 |
| 101 租户   | 本租户公共                                           | 租户管理员维护现金流净 GMV。102 可配置独立别名及术语指向                                       |
| 平台       | 全部登录租户用户                                     | 平台管理员维护全局「下单订单数」。租户没有适配绑定时可查看公共定义，查询时提示当前不可执行     |

定义可见、绑定可用、可读取业务数据三项分别标注。公共摘要不含租户私有别名、表定位、连接标识或查询结果。显式指定正式名称优先尊重用户意图；竞争的同名口径若结合当前问题和前文仍无法区分，Chat 展示可见选项的名称、范围、计算差异与时间字段，等待选择。同名资产不得自动合并，跨租户也不得互相覆盖。

Run 初始上下文只带已发布且可见的少量术语/指标摘要（名称、键、版本、范围标签、一句定义），优先收录与当前提问相关的可见定义。模型可主动检索别名、按业务域缩小候选、读取完整指标定义再查询。选择反馈属于当次任务；有维护权的用户可在工作台修订别名和公共定义。

一次未命中目录、经授权完成并得到用户认可的开放查询，仅产生可抽取素材。平台的「定义指标」、Chat 主动建议保存、用户后续明确要求保存，都应能组成同一种候选定义。候选卡显示问题与来源运行、拟定名称、含义、公式、粒度、时间、单位、维护归属、发布使用范围、拟绑定及缺口；可在预览时修订或放弃。用户确认保存草稿后，正式绑定由数据负责人核验，发布后才进入正式目录。原始一次性日期或门店值应由维护者确认是参数或固定业务条件。公开共享还需检查来源和共享权限，未经授权的用户只可在允许的范围内提出建议。

## 7. 业务验收样例

以下样例是主 PRD 功能验收的内容夹具。实施时冻结两个租户的受限身份、底表快照与可见截止时间，数值样例独立于模型给出的答案。

| 案例                 | 输入与预期结果                                                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目录与来源           | 用六个业务键逐一定位到所有者、适用范围、正式名称、单位、时间、关系和执行绑定。销售、营销、库存各有至少一个完成审批并可查询的样例。标明需要成本权限或源侧缺字段的资产不可误设为可执行。              |
| 公共阅读、分租户计算 | 101 和 102 都能读公共订单数定义，各自仅查询本租户订单；移除 102 的本地绑定后，定义仍可阅读，查询给出未配置反馈。101 的财务指标对 102 的搜索、补全和默认上下文均不可见。                             |
| 术语消歧             | 同一账号分别问成功支付、财务确认和扣退款的销售额，按当前权限匹配对应指标。仅问销售额且前文不明确时展示可见选项，确认后返回所选版本。                                                                |
| 基数与历史时点       | 使用第 4 节跨月样例。增加一条失败支付、再将退款拆为两笔合计 20 元，支付额保持 100 元。调早可见截止时间后，尚不可见的退款不计入并显示对应数据状态。                                                  |
| 平台归因与库存       | 分子为 90 元、消耗 30 元时净 ROAS 为 3 倍；消耗为零或归因覆盖未知时返回不同原因。地区专员无法执行全租户归因。相邻两天可用库存分别为 8 件和 5 件时，完整快照下的期末库存为 5 件。                    |
| 新口径沉淀           | 对尚未登记的指标完成开放查询并由用户确认；同轮建议和次轮「把刚才的口径存下来」均回指正确结果。抽取草稿能区分临时日期、固定规则与共享范围，拒绝/取消保留原分析，确认后经双角色审批才能对其他人发布。 |

上线前由对应责任人确认真实租户与岗位映射、术语指向、支付成功的生产时间字段、归因模型、结账/快照完整度及各租户授权绑定。教学样例的选择不自动写入业务租户配置。
