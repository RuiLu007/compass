# 第 22 课｜Compass 语义层架构评审

## 评审结论

**通过技术方案评审，可进入实现。** 第 22 课[技术方案](../design/TECH_DESIGN.md)已为现有运行时中的五处耦合指定替换入口和兼容路径。新部门采用已有计算能力时，维护者通过 Registry 发布资产、作用域默认值和本地执行绑定，运行时沿用既有工具及场景提示词。遇到新的计算原语或来源授权协议，工程侧扩展对应的算子或适配器。本文检查对象为方案与 Compass `d5d36e5` 的接入基线。数据库迁移、运行时行为和课程六项指标的实测结果属于后续实现验收。

方案 §2 明确区分当前成员授权、置顶摘要和按显式继承生效的默认口径。§3 的 SOP 指导模型何时解释、检索、执行、澄清或提议保存。§4 将选项交给用户，将结果和草稿绑定到版本与权限。§5 要求在同一应用镜像、工具 Schema 和提示词发布版本下更换业务数据复测。这里的“通用”可以在接入下一套业务内容时直接检验。

## 原型与实现分工

[静态 HTML](../spec/METRIC_WORKSPACE.html)使用内置指标、示例数字和本地对话处理函数演示确认卡。产品实现消费服务端签发的候选列表、草稿版本和回执。换一种表达、选项顺序或部门显示名后仍可选择、修改和取消。用户确认查询结果、确认保存草稿、审批发布分别产生独立动作。

## 实现验证

以下剩余风险优先纳入 §5 的实施测试。**优先级 P1** 是旧 Run 恢复和源端撤权。启用 Registry 前，Agent 负责人需验证旧策略 worker 可按摘要唤起。Web 与 Agent 负责人需联合验证来源复核失败后，前端、模型及报告均看不到旧值。其余验证随功能切片执行。

- **内容可移植性。** 用相同的运行时工具和提示词，换一组使用不同词汇、部门标签和物理表名的资产、作用域及绑定。核对默认摘要、发现、同名澄清和执行结果。向已有适配能力增加普通指标时，变更应限于治理数据与执行制品。
- **恢复与撤权。** 保留一个旧版在途 Run。另用新版 Run 发起一次会话内的搜索、选择和草稿提议。撤销成员资格或源端授权后，分别重试决策、模型续轮、读取报告和保存草稿。检查重试时使用的绑定、返回给前端的投影和实际送模上下文。
- **治理完整性。** 两个标签页同时确认同一草案应产生一条草稿记录。改过定义摘要或可写范围后再次使用旧卡应提示重新确认。普通选择和草案确认均不改变当前已发布指标。
