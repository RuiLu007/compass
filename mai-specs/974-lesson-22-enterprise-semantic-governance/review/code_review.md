# 第 22 课代码评审

本次对照规格与当前工作区检查 Web 管理入口、BFF、Registry、Agent 工具装配、Run 恢复与数据库授权。比较基准为 `d5d36e5`，评审包含当前第 22 课的未提交实现及其依赖的已有工作区代码。

复核时，单一开放结果已进入可编辑卡，确认后却重放了模型消息，原 Run 因输入不同而失败。现有所有已确认的草稿均凭原回执保存，写前核验当前执行租约，动作与结果共同记录。唯一和多条回执分别覆盖，重复确认沿用首个草稿。相对时间的查数也会直接触发原轮口径选择，定义解释仍按释义交付。

报告补上正式发布的业务时钟和可见性规则。分页游标关联所有者、Run、清单和搜索条件。下钻核验父分组筛选与已固定的参数，对比在两个窗口授权相同时给出本期减对照期的带符号差额。临时不可用的来源复查会重试一次，已撤销的权限立即生效。

复查又发现三处会影响用户的问题。恢复已执行的目录检索时，搜索轮次会被重复扣减。现将结果、游标与预算在获租事务中一并登记，按原调用幂等返回，重新授权失败时停止重放。按渠道对比会漏算只在对照期出现的金额。现按完整窗口对齐两期所有分组，输出每期合计，并区分空集与缺报。筛选类型不匹配还会反复生成不可执行的查询引用。解析阶段现按绑定的 JSON Schema 返回具体字段和允许类型。

目录全文索引的旧库升级覆盖原生与增量 SQL 两条路径，匹配别名时会先按版本与作用域过滤。Web 就绪检查使用交付清单核对完整迁移链。

整套问题并发运行时，存在已完成外部调用的任务在取消后仍占用名额。复查区分了模型调度前的读取、外部资源回收和调用完成后的本地发布。现在会等待读取收尾，复用已保存的模型输入，并继续核验现有授权。已收到清理回执的操作可释放名额。取消发生在模型结果提交与消息发布之间的 PostgreSQL 用例同时核对检查点、终态和名额。清理状态未知的外部调用继续走原有的恢复流程。

两份复杂分析已经完成正式取数，最终交付分别受到了无来源的百分比和空摘要影响。现将模型服务的结构校验失败纳入一次修订，并在正式回执齐全时生成可逐行复算的分析表。取数范围说明使用已发布定义的真实公式和例外规则；维度合计仅与同一时间窗和授权下另行取得的总计核对。用原始两个模型结果复验，两个文件的分组、数值、修订说明和对账结论均通过原断言。

在新冻结版本中，20 份复杂交付均可由原账户重新打开，其中 19 份通过全部断言。保留的 C009 涉及库存在指定地点的期末数量和同期全范围支付金额。模型把地点条件沿用到了支付查询，表内金额对应实际筛选范围，未回答所问总额。该项按失败计入复杂任务分母。

本课实现通过工程复评。最终冻结版满足识别、同名消歧、正式 SQL、复杂任务及越权阻断的自动验收门槛。识别和消歧的评测标签仍待独立业务人员复核。当前工作区含其他课次的已有变更，本结论针对第 22 课的实现范围。[逐项业务验收](../test/TEST_PLAN.md)
