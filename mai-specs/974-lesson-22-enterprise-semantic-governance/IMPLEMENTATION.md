两个独立租户的销售、营销和库存均有已发布的可执行指标。最终冻结版的 220 个真实 Chat 问题中，识别通过 99/100，同名消歧通过 98/100，复杂任务通过 19/20。20 次无查询权请求均被阻断。经 Registry 和正式绑定执行的 100 个 SQL 用例全部与独立预期相符。识别和消歧使用课程样本的冻结预期，独立业务人员复核仍待完成。[业务验收记录](test/TEST_PLAN.md) · [代码评审](review/code_review.md)

管理链路已从公开 Web 入口跑通。维护者采用真实模型生成的定义，业务专家与数据负责人分别确认，试算使用独立只读连接计算预期。两版发布之间，销售成员读取灰度版，财务成员读取稳定版。回切后，两类账户的列表和详情恢复到同一个旧版本。撤回后，普通成员无法访问该资产。发布记录可回查操作者、理由、来源版本和替换的发布。[发布流程用例](test/verify_management_lifecycle.py)

普通销售成员提交的定义反馈可被维护者采纳为修订。双审发布前读者继续查看原定义，发布后可以查看新定义并用受限源复算。[反馈修订用例](test/verify_feedback_revision.py)

正式查询会标明来源版本、实际授权地区、期间、单位、分组及业务时钟。两期按同一截止时刻和筛选全量对齐。完整的可加金额在一侧缺少分组时按零计算带符号的差额；来源延迟或报表缺行时保留空值。每个完整窗口独立核对合计。下钻沿用原绑定的父级筛选，分页沿用同一使用者、Run 和检索条件。单一有效临时回执可直接进入编辑卡，多条先让本人选取，提交时再次核验来源权限。

发布与撤权在两个已领取的 Run 中一起复验。旧 Run 保留受理时的口径，新 Run 使用后续发布。撤销旧发布后，旧 Run 再次查询得到 403。分页恢复重用原调用的结果，新调用重复搜索则受轮次预算限制。

报告或分析表中的数字、结构有误时，模型会收到一次修订请求。两次均失败时，服务逐项查找用户所需指标的正式回执，核验通过后以 Markdown 或 CSV 交付实际结果，并标明自动解读未通过校验。报告展示已批准的计算公式和订正规则。同一版本、授权、期间和筛选下，同时有维度分组与独立总计时会列出各个维度的核对结果或差额。缺少正式结果或来源失权时停止交付。

第三个租户从管理入口登记了自有 PostgreSQL 表、两种同名口径和新的计量单位。部门与岗位交叉授权、默认口径修改、受限来源试算、分组下钻和两期正负差额均通过。平台管理员通过 PromptOps 发布新场景 SOP，新旧 Run 读取各自绑定的正文，逐组计算仍与相同的独立预期一致。数据库所有者收紧既有行授权后，用户无法重新打开旧结果。[自定义业务域用例](test/verify_configured_domain.py)
