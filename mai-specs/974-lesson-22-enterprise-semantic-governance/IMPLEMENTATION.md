# 第 22 课实施记录

当前工作台维护实体（含关系）、术语和指标。三类定义均可在右侧抽屉查看、编辑，保存即生效。Agent 按问题和前文检索可见定义，有实质歧义时请用户在原会话选择，或填写本次算法。同一业务词不按部门设置默认指标。工作区执行绑定和组织授权继续独立校验。

运行时将单个指标的解析状态返回给模型。缺少正式绑定时，模型仍可读取授权明细、向用户确认口径、汇报已完成的部分。用户填入的计算方法作为本轮已确认的答复恢复，不创建指标或执行绑定。

Chat 的指标保存建议来自模型对本轮结果的业务提炼。候选经过当前可见目录核对，同卡最多三项，逐项展示业务口径、一行计算公式和复用场景。用户勾选后统一保存到个人草稿。明细、探查和历史查询回执继续用于分析与追溯。

在远山总部当前连接上，用原始支付问题复测，三个销售额候选均只有可见定义。选择支付 GMV 后，模型按明细算出 11 月 17 日和 22 日各失败一笔，金额相对上周同日分别减少 191.26 元和增加 784.50 元。另一轮从“都不合适”填写单笔成功支付至少 300 元，11 月 17 日计入一笔，共 671.25 元。点名现金流净 GMV 的会话按成功支付减成功退款直接计算。复测过程中另有两次工具清理状态未确认，单独重跑后完成。

授权抽屉支持多部门、多成员和多资产批量操作。初始上下文默认继承已发布共享术语，实体和指标按当前使用权和问题选取。旧版本的首包偏好保存在历史定义中。任务和场景指令随 PromptOps 发布，来源包扩展随工作区授权启用。详见[架构复核](review/code_review.md)。

零售内容 v3 追加两个租户的销售额释义，历史定义、清单和授权限制保留。下文的冻结题集成绩对应各自记录的运行版本。

管理页当前采用实体、术语、指标的增删改查。从目录或关联对象进入右侧抽屉，预览和编辑共用当前资产。维护者保存后按使用范围立即生效，删除保留历史。第 2 版教学包已补充字段字典、关系和术语定义，正式执行绑定单独治理。

两个独立租户的销售、营销和库存均有已发布的可执行指标。最终冻结版的 220 个真实 Chat 问题中，识别通过 99/100，同名消歧通过 98/100，复杂任务通过 19/20。20 次无查询权请求均被阻断。经 Registry 和正式绑定执行的 100 个 SQL 用例全部与独立预期相符。识别和消歧使用课程样本的冻结预期，独立业务人员复核仍待完成。[业务验收记录](test/TEST_PLAN.md) · [代码评审](review/code_review.md)

管理链路已从公开 Web 入口跑通。维护者采用真实模型生成的定义，业务专家与数据负责人分别确认，试算使用独立只读连接计算预期。两版发布之间，销售成员读取灰度版，财务成员读取稳定版。回切后，两类账户的列表和详情恢复到同一个旧版本。撤回后，普通成员无法访问该资产。发布记录可回查操作者、理由、来源版本和替换的发布。[发布流程用例](test/verify_management_lifecycle.py)

正式查询会标明来源版本、实际授权地区、期间、单位、分组及业务时钟。两期按同一截止时刻和筛选全量对齐。完整的可加金额在一侧缺少分组时按零计算带符号的差额；来源延迟或报表缺行时保留空值。每个完整窗口独立核对合计。下钻沿用原绑定的父级筛选，分页沿用同一使用者、Run 和检索条件。单一有效临时回执可直接进入编辑卡，多条先让本人选取，提交时再次核验来源权限。

发布与撤权在两个已领取的 Run 中一起复验。旧 Run 保留受理时的口径，新 Run 使用后续发布。撤销旧发布后，旧 Run 再次查询得到 403。分页恢复重用原调用的结果，新调用重复搜索则受轮次预算限制。

报告或分析表中的数字、结构有误时，模型会收到一次修订请求。两次均失败时，服务逐项查找用户所需指标的正式回执，核验通过后以 Markdown 或 CSV 交付实际结果，并标明自动解读未通过校验。报告展示已批准的计算公式和订正规则。同一版本、授权、期间和筛选下，同时有维度分组与独立总计时会列出各个维度的核对结果或差额。缺少正式结果或来源失权时停止交付。

第三个租户从管理入口登记了自有 PostgreSQL 表、两种同名口径和新的计量单位。部门与岗位交叉授权、默认口径修改、受限来源试算、分组下钻和两期正负差额均通过。平台管理员通过 PromptOps 发布新场景 SOP，新旧 Run 读取各自绑定的正文，逐组计算仍与相同的独立预期一致。数据库所有者收紧既有行授权后，用户无法重新打开旧结果。[自定义业务域用例](test/verify_configured_domain.py)

## 新建分析的课堂案例

首页第 22 课的四个入口分别覆盖支付失败高峰与部门销售额的混合查询、把临时查询保存为个人指标、自然语言修订原指标，以及销售和财务口径冲突时由本人选择。题面由 PromptOps 发布，课堂账号、数据核对值及纯 NL2SQL 对照方法见[演示说明](../../examples/showcases/lesson-22-semantic-governance/README.md)。

对话修订复用指标版本、草稿及确认机制。维护者核对变更字段后可编辑、确认或取消。Web 在写回时复核归属范围和原版本，按决策编号去重。PostgreSQL 集成用例覆盖预览、无权访问、过期版本、重试及来源保留。销售额解析回执同时保留实际命中的发布映射，确认卡列出候选指标的归期字段。

在租户 101 的授权教学环境中，混合查询一轮获得失败高峰、两期支付 GMV 和差额。对话创建的「成功支付方式种数」可按名查到，保留了查询回执来源。Chromium 分别验证了双部门选择后在原轮次取数、从正确的去重计数回执保存且重试去重，以及键盘取消和确认修订。四个预填入口在 1440 与 390 像素宽度均可操作。
