## 持续审查与修复

- 保留同一个 AgentLoop、Dispatcher、模型持久调用、预算及取消设施。工具注册元数据承载结果适配与完成能力，无独立 Search Agent 或 Verify 调度器。
- 新初始消息省略可选回答元数据，保持既有消息修订与公开投影一致；解决添加 null 字段造成同修订投影冲突的问题。
- 已合格的 partial 可以接受，避免围绕同一个已明确缺口重复修订。
- 完成能力独占批次，混合批次在审批和执行前整体拒绝。发布必须携带根执行域的持久接受记录，正文、引用和附件摘要逐项对应。
- 交付预留基于已结算模型用量和实际延迟估计；硬上限继续由既有预算器执行。父子共享的模型步骤计数也预留交付空间；工作工具减少时清除 Provider continuation，保持原工作阶段身份，恢复重用已保存的请求帧。
- 工具批次耗时也计入交付时间估计，减少临近截止时再启动长子任务的机会。预留属于估计，实际上游延迟和上下文硬上限仍可能使 Run 未完成。
- 原始结果与引用登记中相同的记录只展示一次，登记使用 recordRef 指向同一回执的 JSON Pointer。私有证据保留完整内容；新增单元用例核对嵌套路径、转义、旧协议兼容及记录完整性。
- 子任务只回传证据 ID，父级通过通用导入端口从当前 Run 私有存储读取完整证据，保留原 ID、原工具与调用关系。导入复核来源属于本 Run，原记录保持不可变；子任务中的引用可直接用于父级候选，交付与重放均已验证。语义 Review 保留事实、版本与来源位置，权限复核记录留在服务端。完整账本仍参与摘要绑定及发布权限重验。
- SQL 参数错误附带已有支持函数清单和元信息操作入口；子任务描述明确当前只读能力继承与步骤额度，帮助主 Agent 按实际能力委派。
- 调整既有语义方法中“独立部分已有答案时优先交付”的过早结束指引：可继续的任务先完成，用户澄清或外部条件阻塞时交付已核内容与等待事项。保留原有口径澄清与授权规则。
- Markdown 附件复用已核正文，允许文档来源；查询数据类型约束只应用于 CSV / dashboard。补上文档来源生成 Markdown 的回归用例，避免把报告交付误限为数据库结果。
- 整段原文引用只需段落 ID；精确摘录才填写成对字符区间。无效查询引用反馈具体行列和可用列名。指标适配声明查询时间区间左闭右开，语义审阅复核完整期间及单位换算。
- 课堂装配补齐当前资产授权 API 所需的 21 项指标／实体许可，只授予专用教学分析员；独立金标准保留歧义解析和显式选择，再核对金额与范围。

- 模型单轮超出既有工具批次上限时，整批保持未执行并反馈拆批重提，沿同一 Loop 继续；验证首批无调用副作用及最终交付、重放。

- 候选与 Review 按模型和预算能力分配输出额度，上限 8,192 token；处理原 2,048 token 默认值导致结构化候选截断的问题。截断批次不执行，反馈缩短重提；持久回放验证通过。

- Review 回执仍提交持久检查点，当前 worker 随后完成接受与发布检查，避免在最后一次审阅和交付之间主动交还租约、额外完整重放历史。工作模型步骤沿原调度边界；新增回归覆盖 worker 边界恢复、审阅后连续交付及重复回放。

## 实施细节核对

plain 和 evidence 均采用同主模型 Review，统一检查模式与原问题覆盖。新协议子 Agent 按注册元数据继承当前可见的只读、无固定审批能力；本地变更、写入、递归委派和最终交付保留在父级。动态需要用户确认的工具返回具体确认事项，子任务将其交回父级。父子共享预算，子级结果与证据经既有内部协议返回，父级负责最终候选；旧协议仍保留数据库委派边界。已进入当前上下文的来源撤权沿既有运行权限重验终止 Run，历史正文、引用和附件转为受限投影；新工具调用中的访问拒绝作为普通反馈处理。

正式数据库沿既有迁移，新增状态使用 Run 私有消息，无新增 DDL。验证使用独立测试库、独立端口和私有工作目录；日常服务与历史数据保留。实际检查、运行 ID、失败与跳过项统一记在 [验收记录](../test/ACCEPTANCE.md)。
