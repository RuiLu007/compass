# Feature 988 实施记录

2026-11-11 · 受控自主执行

## 交付

- 同一个 AgentExecutor 循环执行直接查询或 Todo 计划。Verifier 核对两个时段的事实覆盖、来源、金额和排名。最终回答和商品 CSV 使用已核验的查询，商品贡献正文显示品名和 SPU 编码。
- 分类、推理和底层重试在现有可靠执行器内逐次计量。预算、重复查询、无进展、Deadline 和阶段超时可以停止后续工作。保留原 RunControl 的取消与清理裁决。
- v1 流新增可选计划动作和结果摘要。输入框上方的单行浮动条显示环形进度、当前步数和步骤名称，悬停、点击或键盘操作可查看一级事项及状态。完成后短暂显示完成态并自动隐藏。预置「先列计划 · 渠道与商品诊断」使用第 15 课的课堂时段。
- 新增 Agent 配置开关和经核验的 Provider 档案输入。保留现有托管 Retail 绑定，无数据库迁移。启用步骤见[第 16 课运行说明](../../docs/lesson-16-controlled-autonomy.md)。
- UML 的逻辑类型按实现模块落位。`ControlledRun` 聚合计划、验证与预算，`ExecutionPlan` 分别保存定义、进度和完成证据，动作结果通过 `ActionOutcome` 回填观察并生成流事件。停止原因由 `AutonomyStopped` 传递，终态由原 `RunControl` 裁决。

## 验证结果

- `pnpm check`、`pnpm build` 和 Compose 配置检查通过。Agent 常规测试 258 项，Web 常规测试 101 项。
- Agent 受控自主执行专项 15 项通过。专用 PostgreSQL Retail 发布库 3 项通过，覆盖真实渠道、商品查询和核验后的 CSV。模型响应由测试脚本提供。
- 分析输入区浏览器回归 12 项通过，覆盖从预置问题到计划自动隐藏的交互。技术方案 HTML 已在桌面、移动和深色模式下离线检查。
- 部署默认保留 M1。付费模型计费档案和开启后实付调用由实际部署环境验收。

## 本地预置案例回归

- Agent 开发入口透传 M2 开关、预算档案和额度。明确的规划请求在 M2 关闭、Retail 连接缺失或模型缺少工具能力时提前结束，并返回具体原因。
- 预置零售诊断固定进入可执行的零售场景，并核对两个课堂时段。计划登记和完成可同时选择下一项。Retail 核验后将可引用的完成参数返回模型，计划快照仍只进入输入框上方的面板。
- 当前本地 Agent 已启用 M2。DeepSeek V4 Pro 和 V4.1 Flash 分别通过实际 Retail 查询、计划推进和 CSV 生成。浏览器预置案例专项通过。

- 临时查数支持列出表、查看字段、分页和 PostgreSQL 只读 SQL。查询复用工作区 Retail 账号，限制 50 行与 4 KiB。在本地以真实模型验证了查表和按 `ORDER BY`、`LIMIT` 执行用户 SQL。
- 查询卡片显示入参、结果预览和执行中状态。分析摘要随事件更新，终态显示用时。已核验回答在浏览器按时间分段呈现，减少动态效果模式直接显示完整回答。分析轮数上限为 20。
