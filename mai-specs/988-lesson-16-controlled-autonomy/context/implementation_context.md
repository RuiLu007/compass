# Compass 第 16 课实施上下文｜M2

## 前置能力

第 15 课 M1 的同步 AgentExecutor、模型执行与工具分发契约。两种策略沿用同一 Run 与观察结果通道。

## 本课要交付的运行能力

- 提供 ReAct / Plan-and-Execute 策略切换，复杂经营诊断采用轻量 Plan-and-Execute。Planner 生成结构化 ExecutionPlan，PlanExecutor 按依赖推进，实际执行状态独立于计划定义。支持步骤失败、跳过和计划失效处理。
- 关键结论使用独立 Verifier。覆盖 Step-level 与 Run-level 的规则、Schema 和工具结果验证，失败走有限 Retry、Replan 或 Fail。重规划保留已验证结果并更新后续步骤。
- AutonomyBudget 与 StopPolicy 由确定性代码执行。限制步数、工具调用、Token、成本、Deadline、超时与连续失败。检测重复调用和无进展。成功、失败、预算耗尽和需人工介入均给出可区分的结束原因。
- 演示从指标确认、GMV 分解到流量、转化、库存与假设验证。注入数据异常或缺失，观察重查、重规划和预算停止。交付 M2、执行策略选型矩阵、预算与终止策略。

## 课次边界

采用内存执行状态。人工介入只表达终止/移交结果，持久化审批和恢复在 M5。系统级 Eval 在第九篇。

## Compass 接入约束

- M1 的 ReAct 入口与工具观察契约继续可用。预算的度量区分 Run 总量与第四篇单次 LLM 调用的重试、用量和成本信息。
- 硬约束检查在下一次执行前生效，终止原因可检查。额度数值、成本上界及模型用量缺失时的处理策略由技术设计确定。

## 跨课契约

任务以 Run 进入，外部能力经受控接口调用，关键状态变化生成结构化事件。课堂复用同一个 Compass 经营分析案例，每课以可观察的正常和异常结果验收本期增量。
