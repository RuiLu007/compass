## 关键发现

- 用户要求：主模型调用 create_workflow，提交模型编写的编排 DSL 及可复用的输入定义；Workflow Engine 试跑，确认保存后按当前用户和工作区注册为模型可调用的工具。
- 用户要求：sub_agent 单独作为工具，首版仅接受 prompt。子 Agent 使用独立消息上下文和 Agent 循环，可调用获准的内置工具，仅向父 Agent 返回最终结果。工作流可调度同一能力，并用函数调用入参构建子任务 prompt。
- 课堂验收使用两条 Chat 预置：第一次先做有复用价值的查询分析并在最后请求沉淀；第二次换比较周期，使用相同业务目标，由模型自主选择已保存的工作流。
- 代码核对：已有 QuickJS runner、工作流资产、保存邀请及工作流插件页。当前资产仅支持管理与导出，执行需以通用契约接入。AgentStep 已支持 kind 和同 Run 父子关系，公开执行节点有 subagent 类型；首版优先复用这些结构。
- 沿用 Showcase 隔离规范。生产执行器按注册工具和本次函数入参推进，课程日期和示例问题留在 Chat 预置。
