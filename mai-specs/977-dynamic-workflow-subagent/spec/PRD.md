# PRD：第 17 课动态 Workflow 与 SubAgent

> Profile：standard。采用项目 PRD 模板。需求来源为两次课堂闭环说明及随后的合并指示。

[返回需求简报](../BRIEF.md)

## 1. 目标与使用场景

运营分析师先探索一个值得每周重跑的经营问题，得到真实查询结果，然后把经过试跑的分析方法保存为个人工作流。以后在同一工作区提出换了时段的同类问题，主模型根据工具说明选择合适的工作流，并自行填入新的参数。

课堂同时演示两层调用。主模型可以直接委派一个独立子任务，也可以生成编排脚本，让工作流根据入参和中间结果创建子任务。两种入口使用同一套子 Agent 能力。

## 2. 功能需求

| 编号  | 触发和输入                                                                        | 可观察结果                                                                                |
| ----- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| FR-01 | 主模型调用 `create_workflow`，提交名称、说明、函数参数 schema、编排脚本和试跑参数 | 引擎执行编排并返回试跑结果。试跑成功后，Chat 提供脚本、参数和结论的保存确认。             |
| FR-02 | 用户确认保存，随后在同一工作区发起新的 Chat Run                                   | 模型工具清单包含已启用资产的能力说明和参数 schema。调用执行同一版本的脚本并返回本次结果。 |
| FR-03 | 主模型调用 `sub_agent({prompt})`，或脚本用输入构造子任务 prompt                   | 独立进程中的 Agent 循环使用该 prompt 和获准的内置工具。父级接收子任务最终结果。           |
| FR-04 | 学员点击第 17 课的两个预置                                                        | 分别填入探索与保存、换周期复用的可编辑业务问题。用户发送后进入普通 Chat。                 |
| FR-05 | 用户在分析过程中展开工作流或子任务，或重开历史会话                                | 展示实际执行的工作流、版本、子 Agent 节点及状态，保留父子关系。                           |

## 3. 权限与状态

- 每轮从当前用户、租户和工作区加载资产。停用与改名通过已有 Workflow 管理操作完成，后续 Run 使用新状态。
- 用户在「插件 → Workflow」中确认删除自己的工作流后，列表和工具清单移除该资产，历史会话保留执行记录。之后可重新试跑并保存同脚本，生成新的工作流。
- 子 Agent 接收显式传入的 prompt，使用自己的消息、工具观察和续接状态。父 Run 提供可信身份、预算和取消控制。
- 试跑失败时反馈错误并保留当轮分析。成功后由用户确认写入个人资产库。重复确认返回同一资产。
- 旧资产按原契约继续查看与管理。新执行契约、资产和运行状态归 `agent/main`。

## 4. Chat 预置文案

### 探索渠道变化并保存

> 用 Retail 渠道商品日报（core.channel_product_daily）的已支付金额口径，对比 2025-11-17 至 2025-11-23 和 2025-11-24 至 2025-11-30。每个日期、渠道、SKU 和区域取最新报表版本。找出实付额变化最大的渠道（按差额绝对值排序），拆解贡献最大的三项商品，另行核对全量商品汇总与渠道差额是否一致。报告金额、变化方向和日报里能观察到的数据缺口。分析完成后，请把验证过的方法创建为可复用的工作流，将两个日期区间作为入参，并用本次时段试跑。

### 换两周复盘渠道变化

> 我在准备 11 月中旬的经营复盘。请用 Retail 渠道商品日报（core.channel_product_daily）的已支付金额口径，比较 2025-11-03 至 2025-11-09 和 2025-11-10 至 2025-11-16。每个日期、渠道、SKU 和区域取最新报表版本。按实付金额差额的绝对值找出变化最大的渠道，列出贡献最大的三项商品，再用全量商品汇总复核渠道差额，说明金额、变化方向和日报里能观察到的数据缺口。

日期文本按含首尾两日理解。函数入参的含义由创建时的参数 schema 说明，两次对比均使用已授权的课程 Retail 数据。

## 5. 验收标准

| 编号  | 操作与条件                                     | 通过条件                                                                                                     |
| ----- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| AC-01 | 无匹配资产时发送第一条预置                     | 完成渠道、三项商品和汇总核对。主模型实际调用 `create_workflow`，模型生成的脚本使用本次参数试跑，出现保存卡。 |
| AC-02 | 审阅保存卡后确认，再重复确认或重启 Agent       | 确认前资产列表为空，确认后出现同一资产、同一版本和脚本，重复确认成功且数量为一。                             |
| AC-03 | 同一用户开启新会话发送第二条预置               | 请求为普通问题。模型从工具目录自行选择该资产，提交变化后的日期参数，执行同一脚本并以本次数据回答。           |
| AC-04 | 直接委派子任务，随后用脚本串行和并行调度       | 子 Agent 各自开启独立循环和上下文，在实际子进程运行。工具调用受父 Run 授权约束，父模型只收到最终结果。       |
| AC-05 | 尝试跨用户、跨工作区调用，或停用、变更授权     | 未获授权的资产不可见且不可执行。停用后新 Run 移除工具，重新启用后同一工具身份恢复。                          |
| AC-06 | 输入参数错误、脚本失败、子任务中断或取消 Run   | 返回可辨认的失败状态，子进程收敛。失败的试跑不发布保存邀请。已确认的子结果具备可归属的持久记录。             |
| AC-07 | 桌面和窄屏用键盘选中预置、打开保存卡、刷新页面 | 输入可编辑，焦点回到输入区。执行节点可展开，保存状态和脚本可从历史恢复。                                     |
| AC-08 | 打开个人工作流，先取消删除，再确认删除并刷新 | 取消保留原资产。确认后列表和模型工具清单移除该资产，已有执行记录保留，新保存可生成独立资产。 |
