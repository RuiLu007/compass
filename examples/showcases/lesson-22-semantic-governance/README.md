# 第 22 课 · 从一句经营追问到可复用的指标

从「新建分析」输入框下的「第 22 课 · 经营语义与指标口径」选题。点击后可以改写问题，按 Enter 发送。题面保留教学数据的年月，让学员可以原样提问。表名、字段、工具和审批步骤都留给系统处理。

## 课前准备

使用租户 101 的零售教学工作区、可调用工具的 Chat 模型和当前用户获准的只读支付明细。启用 Context Runtime 和工作区经营语义 Registry。销售部账号需要获准查看支付 GMV 并使用其工作区绑定。第二、三题使用同一个具备个人指标维护权的账号。第四题换用销售兼财务账号。课堂使用普通经营问答模式，便于展示查询和治理工具。

在 Prompts 中导入并发布 `support/starters/semantic-analysis.json` 和 `tools/discover_semantic_candidates.json`。前者提供四张卡的[可编辑题面](../../../apps/agent/src/compass_agent/prompts/support/starters/semantic-analysis.json)，后者包含修订字段。环境准备见[指标口径与查询](../../../apps/web/README.md#第-22-课指标口径)。

## 一、失败支付最多那天，销售额也掉了吗？

> 帮我翻一下 2025 年 11 月 17 号那周的支付记录，找出失败最多的那天，再看看当天成功支付的销售额比上周同一天多了还是少了，差多少钱？

支付团队关心失败的尝试，销售部关心成功支付的金额。请销售部学员直接发送第一题。用明细找出失败最多的一天，该日期决定后面两次取数的期间。同一账号可改变问题中的经营事件来选择其他可见指标。

| 核对项   | 课堂观察                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 支付明细 | 只读 SQL 对上海时间 2025-11-17 至 11-23 的失败支付尝试按天计数。遇到并列峰值时说明并列情况，需要选一天继续比较时向用户确认。 |
| 正式指标 | 展开执行过程，查看成功支付指向的指标定义、数据期间和正式取数回执。销售部使用支付 GMV，按成功支付尝试发生时间归期。           |
| 经营结论 | 核对选中日期及前七天同一星期几的金额、单位和有符号差额。失败尝试次数与金额分别列出。                                         |

租户 101 教学快照的核对值为 11 月 19 日失败 10 笔。支付 GMV 在 11 月 12 日为 31,402.35 元，11 月 19 日为 42,339.45 元，增加 10,937.10 元。

**同题对照**　在独立教学实例仅提供相同只读连接和 NL2SQL，关闭该实例的 Registry 和文件指标字典，使用同一账号权限、模型、数据截止和空白会话，发送完全相同的题面。两次都保留执行过程。展开两组的正式指标取数步骤。混合组直接复用已发布的支付 GMV 公式和归期，只填日期参数。纯 SQL 组需要自行确定成功状态、入账时间和金额字段，并把这些规则写进 SQL。课堂上可以逐项核对这些额外工作。若纯 SQL 组追问“销售额按什么算”，讲师按已发布的销售部定义补充，再继续计时。若它自行选了订单金额或渠道日报实付，按正式口径独立复算，记录差异。

| 记录项                                       | 混合查询 | 纯 NL2SQL |
| -------------------------------------------- | -------- | --------- |
| 部门口径、失败峰值日、两期金额和差额逐项正确 | 现场填写 | 现场填写  |
| 探表、试写 SQL、报错重试次数                 | 现场填写 | 现场填写  |
| 人工澄清轮次、首次得到完整正确答案的用时     | 现场填写 | 现场填写  |

上面的日常问法在销售部教学账号中用时约 96 秒，一轮完成，失败笔数和两期支付 GMV 均与独立复算一致。此前纯 NL2SQL 的试跑分别遇到来源权限复核和超时，两组完整正确答案的耗时留待同题对照时填写。

## 二、这周有几种支付方式真的付成功了？

> 2025 年 10 月 1 到 7 号，顾客一共用过几种支付方式？只算付成功的。

先在「指标口径」按名称查找「成功支付方式种数」，用尚未保存等价定义的演示账号开课。遇到临时查询授权提示，可回复“可以，就按这周实际付成功的来算”。核对成功状态、支付尝试时间和支付方式去重规则；日期是本次参数，单位是“种”。租户 101 教学快照中共有 5 种。给学员看本周数值后再决定是否留存。

模型识别出目录尚未覆盖、周会值得持续跟踪的指标时，答案下方会展示业务名称、统计口径、计算公式和复用场景。勾选需要的指标，点击「保存所选」即可存入个人草稿。只要本次数值时，直接阅读答案即可。学员也可以在原会话明确提出“以后周会还要看这个数，帮我存成‘成功支付方式种数’”。核对预览后确认保存，在「数据与语义 → 指标口径」搜索实际保存的名称，第三题沿用这个名称。

## 三、把已有指标的去重规则写清楚

> 帮我把之前存的指标「成功支付方式种数」改一下，说明里补一句“同一种支付方式，哪怕好几天都有人用，也只算一种”。

用第二题的创建者开新分析，点击第三题。目标是库里的同一条个人指标；单独演示时也可以把题面的名称换成自己有权维护的指标。该例把“同一支付方式跨日只计一次”写进业务含义，便于读者区分期间去重和每日去重后相加。

1. 对照预览中的指标名称、代码、当前值和修订值。已经相同的字段会略过。
2. 先点「取消修订」，回到指标口径页，检查原定义。重新发送，再点「确认保存修订」。
3. 在指标库打开原记录，检查代码、来源及归属，查看新版本的业务含义。若有另一位维护者先改了该指标，重新发起修订以核对最新版本。已发布指标的 Chat 修订进入草稿，执行绑定沿用现有治理流程。

## 四、联席会的“销售额”用哪个口径？

> 销售和财务要开联席会，2025 年 11 月 17 号那周的销售额是多少？

换用租户 101 同时具有销售与财务部门身份、且同时有权查询支付 GMV 和确认收入的教学账号。用新会话发送第四题。选择卡应同时列出「支付 GMV」和「确认收入」，说明成功支付与收入确认的差别及对应期间。让学员在选项间切换，确认前保留等待，选定后才查询。

第一次选择销售侧的支付 GMV。重新开分析发送同一题，选择财务侧的确认收入，比较两次结果引用的指标版本、归期和金额。也可点取消，观察本次运行结束。同一账号在新问题中明确说“按收入确认”时，可以直接核对确认收入口径。
