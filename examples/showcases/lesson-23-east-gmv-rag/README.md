# 第 23 课 · 华东区 GMV 为什么下降了 12%？

周一开经营会，华东区负责人看到成交额环比下降 12%。媒体采购说只调整过晚场，仓库说周三已经补货，店长说这周券面额还提高了。财务又收到一张“平台收入少了一半”的旧截图。**区域经理要决定先找谁、改什么、用什么指标判断是否有效。**

这是《企业级Agent工程架构实战营》第 23 课的独立教学案例，负责人为课程维护人。案例以 2025 年 11 月 4 日中午可见的资料回看 10 月 20–26 日，与 10 月 13–19 日对比。场景和账本均为教学合成，单据、日期和金额彼此对应。与原[华东跑鞋投放复议](../lesson-23-agentic-search/README.md)可分别演示。

## 开场直接问

> 帮我看一下，华东区 2025 年 10 月 20 日到 26 日的 GMV 为什么比前一周少了 12%？用 11 月 4 日中午已封版的资料。我下午要跟渠道、仓配和门店开会，请先核实这个数，再说主要少在哪里、哪些解释站得住，以及我应该先安排什么。

首次演示只发这段普通问题，让 Agent 根据每次观察决定下一步。可以随后用一句业务追问改变调查方向：

- “仓库周三就发过到货照片了，为什么还要找仓配？周几开始，顾客买鞋真的顺了？”
- “杭州说涨了券面额，上海怎么没事？门槛和实际让利都帮我算一遍。”
- “退款多了，会不会就是这十二个点？如果我关心的是现金，答案会怎么变？”
- “预算先给我留着。现有资料能把损失算到哪一层？哪项决策值得先做一个小试验？”

## 准备检索与数据源

1. **知识源**。索引 [corpus](corpus/) 下的 12 份 Markdown。每篇带独立文号、版本、负责部门、适用范围和归档时间。目录以外的题面、SQL、讲师参考和检索评测单独存放。
2. **切片与索引**。课程发布器先取 Markdown 二级标题，在 600 字符的目标长度处按完整自然段切分，表格整段保留。12 篇原文生成 131 个片段。标题、章节和正文送入 OpenAI `text-embedding-3-small`，1024 维向量保存在 Web 拥有的 PostgreSQL 数据库。
3. **结构化来源**。按[数据字典](data/README.md)加载冻结账本。单机可用 SQLite 复算，Compass 可用专用 PostgreSQL 只读连接。授权知识检索和数据查询后，使用普通 Chat 提问。为纯检索开发备课时，也可以将召回的段落交给分析员在本地 SQL 工作台复核。
4. **数据隔离**。只有业务原文进入文档索引。数据源发布九张课堂表，讲师结果与评测探针留在 [instructor](instructor/)。本案例无需专用工具、固定的执行序列或生产配置改动。教学工作区停用时可解除两个来源绑定，保留材料供下次重新索引。

## Agentic Search 在这里做什么

经营账能算出哪个单元少卖了钱。下一问随观察而改变。例如，两条跑鞋业务线若分别表现为“少人来”和“人来了但少付款”，它们需要不同资料。前者可查媒体采购的班次和真正买到的有效访问；后者可查货池的尺码、拒绝原因和发布单，再用日期划窗核对经营变化。某项指标保持稳定时，Agent 应把它用作参照，把剩余查询预算放到仍可能改变经营判断的问题上。

讲师可以做三次对照。只读文档，看能解释哪些规则、哪些金额仍缺；只读 SQL，看能量出多少、哪些代码及政策范围仍不清楚；最后开放两类来源，让 Agent 交付一张可加回总盘的贡献表、主要机制、反例和行动。记录每轮实际检索词、读到的章节、所查数据、改变了哪项判断，以及在什么地方决定停止。教学目标是看清一次新观察怎样改变下一次搜索。

[讲师验收](instructor/README.md)给出可复算的数字、归因边界和课堂追问。[检索探针](instructor/probes.json)可单独验收自己的切片、召回与重排。
