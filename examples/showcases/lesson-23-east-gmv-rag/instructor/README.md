## 开会时该先安排什么

1. **直营增长和商品**核晚场预算与可买货池，提出有限额的小额恢复试投。观察实际落地成本、付费支付率与每单实付，测完再决定加量。课堂可以算出发生的差额，未来恢复额度的效果仍要实测。
2. **仓配和平台商品**盯 EAST-FLAG 的 41、42 码，按可售发布监测拒绝率并同步观察旗舰支付率。若开放后仍差，沿其他拒因与结算服务继续查。40 码可作同池参照。
3. **会员运营和城西店长**复核两个门槛之间的折前篮子覆盖，下一轮留出可比时段或门店，同时观察通过率、支付、每单实付与让利。上海可作经营参照。先处理有清楚负责人的问题，再申请更细粒度数据。

## 评审怎样判

- **数字闭合**。时间、区域、支付口径正确；贡献正负相加回到 −12 万元。给出至少一个增长单元、一个稳定参照。扣分点包括把退款再扣进 GMV、重复计算渠道与商品族交集。
- **跨源解释**。媒体同时有授权和实际交付，仓配同时有实际发布、尺码过程及销售窗口，门店同时有有效版本、券漏斗及收银结果。每条主结论记一处命中章节和一项实际查询，允许不同调查顺序。
- **归因边界**。明确区分单元实测差额、与之相符的业务机制和待测的反事实。把缺货尝试逐条折算成损失、把门店差额全部判给试点、把服配增长等同于活动增量，均需退回。
- **资料缺失演练**。临时在评测端屏蔽仓配纪要，仅开放制度及结构化数据。应仍能查出 REL-241 与主销码异常，但少了现场对周三传言的解释。再屏蔽库存事件和日档，只保留营业账时，应保留旗舰单元的 −5 万元，将缺码机制列为待核。比较两次回答的变化。
- **停止条件**。金额已闭合、优先行动有负责人和观察指标、剩余问题需要未提供的顾客级或实验信息时，可以交付。记录实际轮次、重复查询和耗时；没有统一规定的工具调用顺序。

[检索探针](probes.json)中的每个 target 指一个需要命中的文档与二级标题。标题用于匹配切片的父级章节。可分别统计单目标 Top-5 召回率、多目标整题覆盖率，并单列“召回正确但选择了错误版本”的题。课堂答对一道数字题仍需按上述标准检查跨源结论。

## 一次召回与补问对照

在 Compass 根目录运行以下命令。脚本只在内存中建索引，使用 Python 3.10+ 和带 FTS5 的 SQLite，不需要向量服务或模型凭据。

```sh
python3 examples/showcases/lesson-23-east-gmv-rag/instructor/retrieval_baseline.py
```

词法基线按二级标题切出 127 个章节，中文取相邻双字，英文保留完整词，使用 BM25 取前五个章节。18 道口语探针共有 22 个目标，原问题单次检索命中 19 个，15 道题所需材料完整。缺口有三处：恢复日观察窗的仓库纪要、七日售后的最终封版、同名秋跑活动背后的媒体指令。

三道题各追加一次讲师预写的追问，再与首轮结果合并，22 个目标全部命中。两次累计检索最多取十个章节。此项测的是原文可检索性和拆问后新增的信息；接入自己的 RAG 后，可用同样探针另测切片召回、版本选择，以及真实 Agent 能否自主提出这些追问。
