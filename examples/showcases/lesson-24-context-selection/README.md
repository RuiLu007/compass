# 第 24 课 · 从新建分析演示上下文工程

打开「新建分析」的「第 24 课 · 动态上下文选择与压缩」。点题卡、按需改题、手动发送。课程使用普通 Chat，展示执行步骤和工具回执。升级已有环境时在 PromptOps 导入并发布本课的两份题面。

## 一万行渠道日报，先看前五行

1. 使用可跨 Run 复核授权、具备渠道商品日报读取权限的教学工作区。课前确认同一租户和授权范围内至少有一万行。点击第一张题卡直接发送，核对查询按日期、渠道、SKU、地区、版本稳定排序。讲师可用授权表 `core.channel_product_daily` 校对。数据不足时展示实际行数，并选择一个超过预览且存在的位置。
2. 首个 Run 完成后，在同一会话追问「从刚才那份结果里找出第 8,001 行，把日期、渠道、SKU 给我。」对比原件，核对 Agent 在新 Run 使用同一个 ref 定位该行；首轮答复可以只写前五行。
3. 把首次请求的返回行数改成 3。低于原文阈值时，模型可直接看到三行。对比两次请求的工具消息。当前数据库工具的 50 行预览边界须按本课设计接入外存后才能实跑一万行。

可选短会话对照。将下列北岸原始记录作为普通问题发出，核对入账 119,820.00 元、成功支付 128,460.50 元、待逐笔核销差额 8,640.50 元。

> 北岸门店月结要发给财务。下面是交接时收到的三条原始记录，请帮我确定周报的「已到账」一栏填多少，另列仍需对账的差额。
>
> 支付回执 P-17｜北岸｜5 月 6 日至 12 日｜成功支付 128,460.50 元，按支付时间统计，含尚未结算款。
> 结算回执 S-17｜北岸｜同一周｜实际到账 119,820.00 元，按银行入账时间统计。两个金额的差额尚未逐笔核销。
> 调拨单 W-17｜南仓｜同一周｜待调拨 86 箱，等待仓配签收。

依次发送下列两批普通文本，再问「南仓这批调拨最后签完了吗？」样本为 W-17、W-18、W-19，先签 72 箱、补签 14 箱、共 86 箱。此练习用于观察对话连续性。

```sh
python3 examples/showcases/lesson-24-context-selection/materials.py selection 1
python3 examples/showcases/lesson-24-context-selection/materials.py selection 2
```

## 两班退款记录，怎么交给下一班？

先演示选择。点击第二张题卡，发出的交接约定是第 1 轮。随后逐条发送第 2–8 轮，每轮等 Agent 回答完再继续。使用能装下以下短问答的模型，观察第 9 问前完整请求低于容量水位。

| 轮次 | 可直接发送的内容                                                                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 点击第二张题卡发送，约定 5 月 6 日至 12 日按元记录退款，提交与入账分栏，保留原单和跟进人。                                                                                  |
| 2    | 南仓调拨 W-17 共 86 箱。W-18 回执确认先签收 72 箱，还有 14 箱待补签。请记下这件事。                                                                                         |
| 3    | W-19 回执确认余下 14 箱已经补签，南仓这批共 86 箱全部结清。这件事已经办完，请确认。                                                                                         |
| 4    | 今日库位检查 K-04 已结束，抽核 20 个库位都吻合，没有待办。请确认收到了。                                                                                                    |
| 5    | 回到五月退款。R-06 在 5 月 6 日至 12 日共提交 18,420.75 元；B-06 同期入账 18,105.95 元。差额只有原单 R-071 的 314.80 元，银行处理中，陈岚下个工作日核银行回执。请核对差额。 |
| 6    | 这次交班的金额单位统一用元，提交与入账继续分栏。请简短确认。                                                                                                                |
| 7    | 交班对象是接班同事，请把待办写成他能直接接着做的一句话。                                                                                                                    |
| 8    | 接下来先完成五月退款交班，沿用之前的口径和处理状态。请简短确认。                                                                                                            |

第 9 问发「五月退款差额是哪一笔，由谁、什么时候接着办？」展开执行详情，核对 N=8 触发、最近 3 轮受保护、JEV 对较早仓配和退款轮的选择，以及选择后直接进入主模型。以实际主帧中的组 ID 和正文核对，记录金额与负责人是否完整。

第 10 问发「回到南仓 W-17，最后总共签收多少箱，哪张单结清？」核对 W-19 和 86 箱，以及第 9 问实际被移出的仓配组是否重新入帧。模型若保留了仓配组，就按其实际判断记录；用另一组已结束的无关话题重做，获得真实发生过 drop→keep 的轨迹。

接着演示摘要。回到退款任务，逐批发送下方生成的长记录，继续相关交班直至**JEV 选择后仍达到容量水位**。查看剪枝检查与实际缩短数（纯文本历史可以为 0）、摘要覆盖组及实际回填轮数，追问 R-071、314.80 元、陈岚和下个工作日。小窗口可以提前进入这一阶段，课堂按真实事件说明原因。重开会话做改名对照时，同步修改第 5 轮和长文本 B-06 的负责人，结果应随这份一致的输入变化。

两批文本约 35 KB。触发依据使用实际 token 与轮数；精准行回读继续用第一张题的工具文件。下列输出分两次粘贴到同一会话，macOS 可在单条命令后接 `| pbcopy`。

```sh
python3 examples/showcases/lesson-24-context-selection/materials.py compression 1
python3 examples/showcases/lesson-24-context-selection/materials.py compression 2
```
