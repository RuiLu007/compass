# Prompt 资产格式规范

Compass 的模型指令按 [LangGPT 结构化提示词规范](https://github.com/langgptai/LangGPT/blob/main/Docs/HowToWritestructuredPrompts.md)组织。本次格式修订为 `langgpt-format-v2`；运行版本使用 PromptOps 的文件版本和整库快照编号。

## 编写与维护

- 根系统提示词按已有内容使用 `Role`、`Goals`、`Rules` / `Constraints`、`Workflow`、`OutputFormat`。规则、约束和目标逐条使用 `- ` 无序列表；已有明确顺序的流程保留有序列表。
- 提示词的根或片段身份以调用链为准。`tasks/*/system.md` 会拼在公共根提示词之后，属于任务片段。
- 任务、场景、SOP、技能、阶段和工具指令片段使用简短的 `**加粗标题**` 与列表。片段不包含 `# Role` 或 `#` / `##` 章节，避免拼接后重复角色和章节结构。
- 工具的 `function.description` 使用简短用途标题与调用规则列表。参数的名称、类型、必填性、枚举、限制及描述继续由原 JSON Schema 表达，调用示例保持原值。
- 一条独立要求对应一个列表项。原有条件、权限边界和因果关系随所属句子保留。JSON 示例、代码表达式、模板占位符和引文内部保持完整。
- 分类标签、用户示例问题、诊断输入、JSON 示例值及界面短文案按各自的数据格式保存。
- 整理格式时逐句保留原要求，包括权限、审批、预算、数据口径、错误处理、澄清条件、输出协议和调用顺序。问候、自我介绍、额外初始化步骤只在原任务要求时保留。
- 变量使用项目已有的双花括号占位符。变量名称、调用来源、可用范围和替换方式保持稳定，变量说明区使用名称本身，避免新增占位符。新增变量须同时更新调用方契约。

## 实际装配归属

| 资产                                                                             | 实际使用方式                                             | 格式                                                           |
| -------------------------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| `shared/fragments/base.md`                                                       | `harness/context.py`、受管 Runtime 的公共根              | 完整根结构；业务请求拼接后只保留这一处 Role。                  |
| `support/session/title.md`                                                       | 会话标题独立调用的 system 消息                           | 完整根结构。                                                   |
| `shared/policies.json` → `semantic-governance`                                   | 指标维护接口独立调用的 system 消息                       | 完整根结构。                                                   |
| `support/routing/instructions.json` → `classify-flash`、`classify-flash-managed` | Flash 分类请求的主指令，周围可附阶段、交付形式和目录数据 | 完整根结构；辅助内容采用片段格式。                             |
| `tasks/*/system.md`、场景模板、场景 SOP                                          | 接在公共根后，按任务、阶段和使用范围选取                 | 加粗标题与列表。                                               |
| 公共规则、技能、阶段、工具说明、交付修正、SDK 决策 instructions                  | 由调用方组合或嵌入已有请求                               | 加粗标题与列表。                                               |
| 路由业务/澄清/受限/转交/闲聊指令、`support/subagent/analysis.md`                 | 同时有独立调用和追加到公共根后的用法                     | 使用可组合的轻量格式，保留原角色约束正文，不再添加 Role 标题。 |

拼接各片段时保留空行边界。检查最终发送给模型的 system 内容，覆盖任务、阶段、使用范围及主/子 Agent，核对角色数量、标题层级、列表与变量替换；分类调用另核对其输出 Schema。

## 模板变量

模型指令内的变量用变量表标注，片段中使用 `**变量**` 轻量标题。用于用户预填问题的变量在下表说明，预填文本保留自然语言形式。所有模板值由调用方作为非空字符串传入，模板引擎执行单次字面替换。

| 变量            | 使用位置                                             | 含义与来源                                             |
| --------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| `period`        | 经营周报、财务周报                                   | 报告期间，由当前问题中的日期及 Run 受理日期解析。      |
| `unit`          | 经营周报、财务周报                                   | 计量单位，按本轮问题解析；缺省为已核实口径的计量单位。 |
| `audience`      | 经营周报                                             | 报告读者，由使用范围对应的 `scopeProfiles` 配置传入。  |
| `tool_limit`    | `shared/policies.json` 的 `tool-limit`、`workflow`   | 本轮工具调用上限，由运行时工具预算转为字符串传入。     |
| `workflow_name` | `support/starters/analysis.json` 的 `saved-workflow` | 所选已保存工作流的名称，由预填调用方传入。             |

正文中的回执字段、工具入参及 JSON 输出字段按各自契约处理，保持原有字段名。

## 发布

先检查所有随包资产与发布候选的模板、结构和工具契约，再使用 PromptOps 的草稿、预览及发布服务生成新版本。发布时核对原始代次、文件编辑版本和待发布集合，保留原快照及历史版本；已有 Run 继续使用受理时固定的清单，新 Run 读取新版本。

源码与线上已有独立修改时，分别保留各自正文。格式发布只纳入本次整理的文件，未发布的示例、无关草稿和资产结构变更另行处理。
