# ADR 0005：Agent 同库队列与 HTTP Worker 驱动

2026-11-12 · 接受

第 20 课需要异步受理、跨租户公平调度和独立 Worker 失联接管。沿用第 19 课的 Run / Checkpoint / Outbox 与 Redis 流，在 Agent 主库新增 job 和 tenant schedule 两张表，以短事务统一准入和领取。

Agent 保持唯一执行所有者。两个独立 Worker 仅持有不透明 grant，通过专用身份领取、心跳和逐持久边界 advance。每个 Run / epoch / Checkpoint 的内部命令先记录 running，再由 Agent lifespan 任务执行，最终回执与 Checkpoint 原子提交。Worker 不连接业务数据库。

租约失效先撤销 epoch 并排空旧任务，未决效果和资源保留占用；可恢复任务重新排队。运行公开协议保持 M5 v2，调度信息作为可选 Timeline 扩展；内部执行权仅进入平台诊断。

该拓扑提供调度槽隔离和可测试的接管边界。计算仍集中于单一 Agent；Agent 多副本、独立计算 Worker 与外部 Scheduler 留待实际负载需要时建设。实现与运维见 [运行说明](../lesson-20-production-runtime.md)。

| 部署形态                                      | 适用负载与故障边界                                                                                                | 运维与演进成本                                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 单进程模块化 Runtime                          | 小规模、短任务；进程承接受理和执行，进程退出后依靠持久状态恢复。                                                  | 组件少，难以独立控制消费者生命周期与并发槽。                                                            |
| 模块化 Agent + 同库队列 + HTTP Worker（本课） | 两租户并发长任务、人工等待、明确持久边界；Worker 失联由租约和 Checkpoint 接管。Agent 故障由单所有者启动复核处理。 | 复用 PostgreSQL 事务和 M5 恢复链路；两个轻量 Worker 无业务库凭据。计算资源与 Agent 生命周期仍集中管理。 |
| 独立 Scheduler / Queue / 计算 Worker Pool     | 计算量、任务时长或租户隔离要求超出单 Agent 容量，需要计算进程独立扩缩容。                                         | 增加跨服务投递、幂等、授权、资源回收与观测协议，需要独立运维与更完整的分布式故障验收。                  |

本课按全局两个执行槽、每租户一个执行槽验收。以实际排队延迟、Worker 接管时长、占用率和未知效果保留情况检查这组配置，测量结果见[运行与恢复验收](../../mai-specs/984-lesson-20-production-agent-runtime/test/ACCEPTANCE.md)。若持续积压来自计算容量或要求按租户隔离计算进程，再推进第三种形态；当前实现保留同库原子受理与持久边界协议。
