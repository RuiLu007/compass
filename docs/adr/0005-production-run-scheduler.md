# ADR 0005 · 多副本 Agent 与同 App 的 Scheduler 角色

2026-11-16 · 第 20 课部署决策

即时与定时任务共用 Agent 主库中的受理事务、队列和持久执行边界。HTTP Agent 按 Run 领取租约，各副本可以接单、执行与发布。Scheduler 单实例负责按期交付、退避和摘要同步，沿用同一个 Agent 镜像与受限数据库登录。Scheduler 停机期间即时执行照常，恢复后按持久触发处理。

| 形态                                | 适用条件                                                        | 运行成本                                                           |
| ----------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| 单进程 Agent                        | 短任务、低并发或课堂初期验证。故障后整个进程重启。              | 部署简单，执行和接单共用进程生命周期。                             |
| 单 Agent 与 HTTP Worker             | 可隔离领取、心跳和推进驱动。模型与工具计算在一个 Agent 上执行。 | 多出内部推进协议及消费者凭据，执行仍受一个 Agent 的计算容量约束。  |
| 多副本 Agent 与单 Scheduler（本课） | 多租户长任务、人工等待、跨实例恢复和定时交付。                  | 共用 PostgreSQL 和 Redis。轮询、回收、发布世代及角色权限需要验证。 |

同库队列使用有界领取与短事务准入锁，模型和工具调用在事务外运行。PostgreSQL 持有运行状态、消息投影和发布租约，Redis 在单 Run 内按包身份追加。未知的外部效果保留待核对。

若持续积压来自新的计算或租户隔离要求，再引入独立执行池或 Broker。单、双副本对比使用相同配额与依赖，观测实际并行、排队和恢复时长。升级停旧写者并保留数据库、Redis 和密钥，回到旧版时使用匹配的隔离备份。[运行说明](../lesson-20-production-runtime.md) · [课堂验收](../../mai-specs/984-lesson-20-production-agent-runtime/test/ACCEPTANCE.md)
