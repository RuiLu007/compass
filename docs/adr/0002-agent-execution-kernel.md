# 0002 · 进程内 Agent 执行内核

日期：2026-11-10。状态：active。依据：[Feature 989 技术方案](../../mai-specs/989-lesson-15-agent-execution-kernel/design/TECH_DESIGN.md)。

## 决策

Compass 第 15 课在 `apps/agent` 内实现一个进程内、单 Agent、同步返回的执行内核。一次分析请求创建一个 Run；执行器使用显式 async ReAct 循环按顺序推进 Step，在同一 Run 内完成 Model → Action → Observation → Model。模型调用继续复用既有 LLM Runtime、路由、可靠执行、容量门和 Trace，不引入第二套模型适配或重试机制。

Run 与 Step 当前只保存在 Agent 进程内。每个 Run 有独立 `RunControl`，集中拥有绝对期限、活动阶段、停止原因、资源清理回执和唯一终态。浏览器经 BFF 打开一条 `compass.run` v1 SSE；Agent 在任何分类、模型或工具派发前先发 `run.started`。停止使用独立 POST，原流负责在在途阶段退出后返回终态。终止受理和正常结果提交由同一事件循环内的无等待状态转换裁决。

本期只提供代码内系统提示词和一个 `retail_sales` 工具。工具不接受 SQL 或连接参数，只接受固定日期、维度和渠道字段；服务端将其映射为参数化只读 SQL。每次查询使用专属 psycopg 异步连接和显式只读事务，核对登录角色、只读状态及事实表 RLS。停止时取消数据库命令，等待原命令退出，再回滚并关闭连接；无法确认清理时不复用资源，Run 以 `cleanup_unconfirmed` 结束。

成功 Run 最多随终态交付一份有界 CSV。Agent 从本 Run 最近一次成功的商品拆分结果生成文件；BFF 和页面同时校验来源 Step / ToolCall、行数、字节数和文件名。页面仅在成功终态且流干净结束后提交回答、历史和 Blob 下载入口。

## 边界与理由

- 选择显式轻量循环，是因为本期只有一个 Agent、一个固定工具和顺序调用。Agent SDK 或图执行框架会引入新的状态、取消和资源所有权，而当前需求尚不需要图分支或恢复。
- 选择进程内 Run 注册表，是因为本期 Run 与 HTTP 请求同生命周期，并明确采用单 Agent 副本。持久 Checkpoint、跨请求等待、Worker 接管和断线续流由第 19～20 课交付。
- 选择 Agent 分配 Run ID、原流输出唯一终态，是为了让启动、停止、断流和完成竞态在同一所有者内裁决。BFF 不推断或合成成功终态。
- 选择查询级专属连接，是为了给数据库取消、事务回滚和故障隔离提供清晰边界。连接开销是 M1 可接受的课堂取舍。
- 选择 SSE 传进度、独立 POST 传停止，是为了保留浏览器可观察的单请求执行过程，同时不让停止动作等待原响应方向可写。

## 协议与安全约束

Agent → BFF 与 BFF → Chat 都使用 `compass.run` v1。每段响应独立连续编号，首包必须是 `run.started`，终包必须是唯一 `run.finished`，终包后只能干净 EOF。核心事件严格校验；未知可选扩展可过滤，必需扩展拒绝。两段均使用 `private, no-store` 并关闭代理缓冲。

BFF 在数据库授权事务结束后才连接 Agent。浏览器只提交页面范围、问题、完整成功历史与模型选择；可信用户、租户、工作区和用途由 BFF 构造并通过私有头传递。Agent 使用部署绑定选择 Retail 身份，浏览器字段和模型输出都不能选择数据库凭据或扩大数据范围。

日志只记录 Run / Step / ModelCall / ToolCall 标识、枚举状态、耗时和安全错误码。模型正文、工具原始结果、续接令牌、凭据和内部推理不进入结构化运行事件。

## 后果

- 单进程最多 8 个活动 Run；一次 Run 最多 6 个模型 Step、每步 4 个工具调用，总期限 180 秒。
- Agent 进程重启会终止活动 Run，已结束 Run 只保留短期、轻量终态摘要，不能恢复。
- 部署必须保持 Agent 单副本，且停止请求与原 Run 命中同一进程。
- 未配置完整 Retail 绑定或不满足 libpq 取消能力时，Chat 仍可走零工具回答，但不开放 Retail 工具。
- 并行工具、统一 Tool Executor、Sandbox 和受控 Artifact 属第 18 课；计划与预算属第 16 课；持久恢复与异步调度属后续课次。

## 验证

实现以 Feature 989 的 AC-01～AC-15 为准。最小门禁包括：同轮多调用 ID 配对、多轮真实查询、参数前置拒绝、模型和工具失败收口、唯一终态、BFF 双侧授权、SSE 截断与非法顺序、文件来源、浏览器折叠与清理，以及模型生成和真实 PostgreSQL 查询两条在途终止路径。
